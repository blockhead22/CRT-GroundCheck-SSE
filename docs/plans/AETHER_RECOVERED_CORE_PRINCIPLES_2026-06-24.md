## Recovered Ideas Worth Keeping

1. Continuity is the product contract.

   The early Lumi work was already trying to solve a real problem: an assistant should carry useful identity, preferences, context, and prior commitments forward without pretending every turn is isolated.

2. Belief and speech should be separated.

   The old Mirus/Holden split survives as a good architecture idea. One layer should ingest, score, and govern memory-like beliefs. A separate layer should reconstruct a response for the user with quality gates, uncertainty, and style.

3. Contradiction is a disposition, not just an error.

   CRT's strongest idea is that contradiction can be resolvable, held, evolving, contextual, or policy-bound. Aether should not merely detect contradiction and panic. It should preserve the state, explain it when useful, and route future trust through it.

4. Memory is a region, not a point.

   The "splat" idea remains useful: memories should carry uncertainty, source, confidence, volatility, recency, authority, and evolution. A single vector or summary is too flat for durable personal context.

5. Trace is the training and evaluation signal.

   CogniMap-like traces should become modern meaning trace graphs: what was retrieved, what was trusted, what contradicted, what was compressed, what was expanded, what was rejected, and what changed over time.

6. Compression should mean semantic/context compression first.

   The file-compression branch produced useful intuitions, but the credible current claim is not arbitrary lossless file compression. The credible claim is memory-state compression and semantic context packing with measurable reconstruction and answer-fidelity tests.

   The recovered `C:/filecompression` folder confirms this. The raw byte API failed as file compression, while the later text/image embedding experiments point toward the useful lane: representation compression measured against reconstruction, retrieval, and downstream behavior.

7. Vectors retrieve; structured checks adjudicate.

   The compression labs were clear: vector similarity is useful for finding nearby context, but it is not enough for truth, contradiction, authority, or policy boundaries. Aether needs vectors plus slots, source metadata, NLI-style contradiction checks, and route policy.

8. Smaller/local models can become useful through scaffolding.

   The goal is not to beat frontier models raw. The goal is to make smaller models more coherent, grounded, and useful through memory, trace, continuation, routing, and reviewed reflection.

9. Depth is an engineered behavior.

   "Go deep", "spiral", "verbose", and "dig in" should not be treated as vague style requests only. They should trigger planning, expansion, self-checking, continuation, and a final response length/coverage check.

## Old Ideas That Were Wrong Or Overclaimed

1. Lossless semantic file compression is not proven.

   The early compression work includes reversible baselines and manifest-based chunk storage, but it does not prove arbitrary bytes can be semantically compressed and reconstructed exactly through a learned meaning layer.

2. "File compression" should not be the public framing.

   Unless byte-exact benchmarks prove otherwise, the current Aether language should be memory-state compression, semantic context compression, and traceable reconstruction.

3. Mirus/Holden were not production-grade learned codecs.

   They were valuable architecture sketches and prototypes, not finished encoder/decoder systems with reliable reconstruction guarantees.

4. DNNT/adaptive-backbone language was mostly aspirational.

   It can inspire learned-codec experiments, but the current roadmap should not depend on a custom transformer backbone until evals justify it.

5. "Self-awareness" language should be tightened.

   Use self-model, continuity model, reflection pass, or evidence-based reflection. Avoid claims that imply consciousness or mystical agency.

6. Vector similarity alone cannot govern memory.

   Similarity is not entailment. It cannot safely decide whether a new claim supersedes, contradicts, qualifies, or merely resembles an old one.

7. Too many mythic names create product fog.

   Lumi, CRT, Mirus, Holden, CogniMap, MMH, and similar names can remain lineage names, but the current product and roadmap should use clear operational labels.

8. Compression quality is not only size.

   A compressed memory/context state is only useful if it preserves task performance, contradiction handling, source traceability, and reconstruction fidelity.

## Experiments Worth Re-running

1. Contradiction disposition eval.

   Build cases that distinguish resolvable contradiction, held tension, evolving user preference, contextual exception, stale memory, and policy-bound refusal.

2. Multifactual deep-spiral eval.

   Test long, emotionally/personally dense prompts with many facts, jokes, requests, and style cues. Measure whether the system pulls the right anchors without flattening the user's voice.

3. Depth and continuation eval.

   Verify that "dig deep", "verbose", "spiral", and similar requests trigger planning, expansion, continuation, and coverage checks rather than only a longer first draft.

4. Compressed context versus raw context benchmark.

   Compare answer fidelity, contradiction handling, and source recall when using raw context, summarized context, and structured compressed memory-state context.

5. Variance probe reruns.

   Run the same task across repeated model calls and model backends. Measure anchor retention, contradiction drift, route choice, and response completeness.

6. Programming robustness eval.

   Use code-context tasks to test whether Aether can answer practical programming questions with retrieved file context, stable reasoning, and clear uncertainty.

7. Belief/speech gap eval.

   Test whether the system can hold an internal belief state while speaking cautiously when confidence, authority, or policy boundaries are incomplete.

8. File-compression sanity benchmark.

   Keep this explicitly separate. Byte-exact arbitrary-file compression must pass hard round-trip tests before it can influence product claims.

9. Representation compression replay bench.

   Re-run the useful part of the old `C:/filecompression` work with modern baselines: raw embeddings, PCA/SVD, quantization, learned autoencoder, structured memory-state scaffold, and summary-only context. Score reconstruction, retrieval retention, contradiction disposition retention, answer fidelity, traceability, token/byte savings, and latency.

10. Trace-as-training-signal review.

   Treat failed responses, degraded reconstructions, contradictions, and corrected traces as reviewed examples for future consolidation and eval generation.

Keep this next.

- Design Code Context Tools V1 around file discovery, focused reading, symbol/path summaries, and answer-grounding.
- Add programming evals that test practical code questions, not only chat-style answers.
- Measure whether context tools improve smaller-model performance versus ungrounded generation.

### Phase 1.7: Reviewed Reflection And Background Consolidation

Move forward, but keep it reviewed and trace-first.

- Replace "subconscious loop" language with reviewed reflection/background consolidation.
- Add queues for candidate memories, contradictions, stale anchors, and useful traces.
- Require provenance and user-visible review state before durable memory mutation.

### Phase 1.8: Contradiction Disposition Governance

Add this as a distinct roadmap lane.

- Implement contradiction dispositions: resolvable, held, evolving, contextual, stale, and policy-bound.
- Surface contradiction state in traces and saved memory records.
- Teach answer assembly to say "this may have changed" or "I have competing records" when appropriate.

### Phase 1.9: Memory-State Compression Evals

Add this before any larger product claim around compression.

- Benchmark raw context, summaries, vector-only retrieval, and structured memory-state compression.
- Score answer fidelity, contradiction handling, source traceability, and token savings.
- Add a representation compression replay bench inspired by `C:/filecompression`,
  but measure whether useful behavior survives rather than whether arbitrary
  files round-trip through a learned latent.
- Keep arbitrary file compression out of scope unless byte-exact tests are explicitly revived.

### Phase 2: Meaning Trace Graph

Treat the old CogniMap idea as a modern trace graph.

- Connect saved traces, memory candidates, contradiction dispositions, route choices, and reflection outcomes.
- Make the graph useful for debugging and eval generation before making it decorative.
- Use trace failures as the source of the next eval set.
