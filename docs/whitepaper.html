Overview

CRT is a contradiction-preserving, trust-evolving framework for governed AI memory and response verification. Rather than treating contradiction as something to overwrite or hide, CRT treats contradiction as a first-class signal. Memories are not flattened into a single mutable truth state. They are tracked, weighted, resolved, and preserved through an append-only logic that favors auditability over convenience.

The system sits closer to a control plane than a generator. It is designed to wrap language models, not replace them. The model speaks, but CRT governs what is trusted, what is contradictory, what remains unresolved, and what should be shown back to a user as stable, unstable, or under review.

Over time, the stack has matured into several aligned layers:

CRT proven

The core engine. Manages memory states, disagreement persistence, drift detection, and resolution tracking.

GroundCheck proven

SSE proven

Aether active

Core Thesis

Most AI systems treat memory as overwriteable cache, contradiction as bug, and verification as optional cleanup. CRT rejects that framing.

Principle 1
Contradictions should be preserved before they are resolved.
Premature resolution destroys information. The system must hold tension until it has evidence to choose.
Principle 2
Trust should evolve continuously, not as a binary flag.
Memories gain and lose trust over time. Negative evidence carries stronger weight than positive reinforcement.
Principle 3
Speech and belief must be separated.
A model may generate plausible language. That does not make it believed. Speech can speculate. Belief must be earned.
Principle 4
A memory system should expose uncertainty honestly rather than collapse it.
If the system does not know, is split, or is unstable, it should show that state instead of pretending certainty.
Principle 5
Variance under perturbation is not noise alone. It can reveal how a model governs meaning.
Temperature-swept sampling exposes fragility landscapes that single-point evaluation cannot see.

Every AI system that flattens contradiction is silently destroying information. CRT preserves the tension so the system can learn from it rather than pretend it never existed.

-- Why this matters

Problem Statement

Modern agents are good at producing fluent output, but weak at epistemic bookkeeping. Common failure patterns include:

  • Contradictions being overwritten instead of preserved
  • No durable record of why two claims conflicted
  • Memory treated as raw retrieval rather than governed evidence
  • No distinction between what was said and what is actually trusted
  • Hallucination checks running too late or too expensively
  • No visible path from user feedback to trust evolution
  • Systems that appear coherent only because conflict has been flattened

CRT is designed as a response to those gaps. Not by making models smarter, but by wrapping them in a governance layer that tracks what is known, what is contested, and what remains unresolved.

Architectural Principles

Contradiction as signal

Contradiction is not automatically failure. Sometimes it marks ambiguity. Sometimes it marks growth. Sometimes it marks a real unresolved conflict in evidence. The system preserves that distinction rather than collapsing it.

Belief vs speech separation

A model may generate language that is plausible, hedged, or mistaken. That does not mean the system should adopt it as belief. The model is the mouth. The persistence layer is the self.

Memory-first governance

The system does not let fluent generation overwrite memory-backed structure without accountability. Memory is governed semantic history, not a cache to be silently updated.

Trust as continuous state

Trust exists on a range, not as yes/no. Negative evidence reduces trust faster than positive evidence increases it. Trust participates in retrieval scoring and verification decisions.

Transparent failure

If the system does not know, is split, or is unstable, it shows that state. No pretending certainty. No silent consolidation. The UI makes epistemic behavior inspectable, not magical.

Contradiction Ledger

The contradiction ledger is one of the most important parts of the system. Rather than deleting one side of a conflict, the ledger stores both sides and tracks their status over time.

StateMeaningAction
DETECTEDTwo claims conflictLog both, classify disposition
ACTIVEContradiction under reviewGather evidence, check user input
SETTLINGEvidence accumulating toward one sideTrust asymmetry building
SETTLEDOne side earned higher trustLower side demoted, not deleted
ARCHIVEDResolution complete, history preservedBoth sides remain in ledger

The ledger is not a debug tool. It is a memory governance mechanism. It supports auditability, user-guided resolution, non-destructive epistemic history, and trust evolution based on outcomes.

Trust Model

CRT uses a continuous trust model rather than binary truth flags. Memories gain or lose trust over time depending on confirmation, contradiction, user correction, provenance quality, and resolution outcomes.

  • Trust exists on a range, not as yes/no
  • Negative evidence reduces trust faster than positive evidence increases it
  • Trust participates in retrieval scoring and verification decisions
  • Contradictory memories are not automatically discarded
  • Provenance quality affects initial trust assignment

This allows the system to represent uncertain but relevant memories without pretending they are settled truth.

Grounding and Verification

GroundCheck and SSE work together to verify claims against stored evidence and current retrieval. This matters because language models often sound most confident exactly when governance is weakest.

  • Extract claims from model output via SSE
  • Retrieve supporting or conflicting evidence from memory
  • Run lightweight grounding checks (sub-2ms target)
  • Expose pass/fail or confidence behavior in the UI
  • Block obvious hallucinations and contradiction drift

Fast enough for live usage. Interpretable enough for inspection. Strong enough to catch the failures that matter.

Variance Probing Research validated

A major result from this project: repeated temperature-swept probing reveals model-specific fragility landscapes.

This work asks a different question from standard benchmark evaluation. Instead of asking whether a model gets a prompt right or wrong once, it asks how the model's semantic output deforms under controlled perturbation.

Two Axes of Difference

Standard benchmarks ask if a model gets it right. Variance probing asks whether the model knows it knows -- and reveals that most apparent confidence is trained uniformity, not genuine certainty.

Why Variance Matters to CRT

Variance is not only an analysis artifact. It serves as a governance signal.

  • High susceptibility becomes an epistemic fragility tag on model outputs
  • Stable multi-cluster response clouds map to unresolved or plural belief states
  • Held contradictions map onto systems that preserve conflict rather than flatten it
  • Dynamic trust damping in fragile regions prevents false confidence
  • Routing decisions can be made based on regime type per model and domain

The probe is useful not only for studying models from the outside, but for designing memory systems that know when certainty is genuine, when it is trained uniformity, and when contradiction should be preserved rather than erased.

The problem is not switching mouths. The problem is losing the self between them.

The governance layer uses this to know what to watch for after every handoff.

Immune Agents in progress

Instead of fixed pipeline gates, the system uses specialized agents -- each one trained to detect a specific violation of the Mirus/Holden constitutional doctrine. They are not tied to pipeline stages. They watch the same stream and fire when their pattern is detected.

Law 1
SpeechLeakDetector built
Speech cannot upgrade belief. Watches the output-to-memory write path. Blocks generated claims from being stored with higher trust than evidence supports.
Law 2
TemplateDetector built
Low variance does not imply high confidence. Detects hedge-template lock vs genuine certainty using susceptibility data and pattern matching. Directly calibrated by the variance experiment.
Law 3
PrematureResolutionGuard planned
Contradiction must be preserved before resolution. Blocks resolution attempts on contradictions classified as HELD, EVOLVING, or CONTEXTUAL.
Law 4
MemoryCorruptionGuard planned
Degraded reconstruction cannot silently overwrite trusted memory. Compares old trust score vs new reconstruction fidelity. Blocks downgrades.
Law 5
GapAuditor planned
Outward confidence must be bounded by internal support. Measures the gap between expressed confidence and belief-layer backing. Logs every divergence.

The coordination layer between agents replaces the original GFN (Graph Function Network) concept. It is not a pipeline graph. It is a communication layer between immune agents that need to arbitrate when multiple laws fire simultaneously.

-- Why this matters

The Persistence Layer Thesis

If governance, memory, contradiction state, support state, and task continuity live outside the currently active model, then the model becomes the mouth -- not the self, not the belief-holder, not the continuity layer. Just the speaker.

This means switching models is safe only if continuity of governance is stronger than continuity of model. The system needs a layer that survives the switch and carries forward:

  • The task intent
  • The confidence and support state
  • The unresolved ambiguities
  • The contradiction state
  • The behavioral constraints and governance policy

Without that, a router is saying "good luck, new brain." Each handoff risks a tiny identity wipe. New assumptions creep in. Tone changes. Certainty changes. Missing details get invented. The task mutates.

Three Requirements for Serious Agentic Systems

Shared Task State
What are we doing. What has been decided. What is still open.
Shared Support State
What do we know and how well. What is grounded. What is fragile.
Shared Governance State
What rules apply. What laws are active. What the fragility map looks like for the current model.

If any of these reset at handoff, the system can drift even when every individual model is working as designed.
