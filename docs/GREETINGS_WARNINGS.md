# Greetings, Warnings & Response Behavior

**Version:** v2.0+ (March 24, 2026)
**Files:** `personal_agent/runtime_config.py`, `routes/chat.py`

---

## Overview

CRT includes several behavioral systems that shape how responses feel to the user — greeting messages, conflict warnings when facts contradict, provenance footers citing sources, and response variation to avoid sounding robotic. These are configured via `crt_runtime_config.json` and the `_DEFAULT_CONFIG` in `runtime_config.py`.

---

## Greeting System

**Config key:** `runtime_config["greeting"]`

When a user starts a new conversation or returns after being away, the system generates a contextual greeting based on absence duration and time of day.

### Configuration

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `enabled` | bool | `true` | Master toggle for greetings |
| `style` | string | `"time_based"` | `time_based`, `time_of_day`, or `simple` |
| `min_absence_for_greeting` | int | `3600` | Seconds of absence before "welcome back" (1 hour) |
| `templates` | dict | see below | Customizable greeting templates |

### Greeting Styles

**`time_based`** (default) — considers how long the user was away:
- Minutes: "Welcome back!"
- Hours: "Welcome back! It's been {time_delta} since we last chatted."
- Days: "Hey {name}! It's been {time_delta}. Good to see you again!"
- Weeks: "It's been a while, {name}! ({time_delta}) Welcome back."

**`time_of_day`** — based on current time:
- Morning (6-12): "Good morning{name_suffix}!"
- Afternoon (12-18): "Good afternoon{name_suffix}!"
- Evening (18-22): "Good evening{name_suffix}!"
- Night (22-6): "Hello{name_suffix}!"

**`simple`** — minimal, no time awareness.

### Template Variables

| Variable | Value |
|----------|-------|
| `{name}` | User's first name, or "there" if unknown |
| `{name_suffix}` | `", Name"` or empty string |
| `{time_delta}` | Human-readable duration (e.g., "2 hours", "3 days") |

### New User Detection

If no previous interaction exists, the system uses the `new_user` template:
> "Hey! I'm Aether. What's on your mind?"

## Conflict Warnings

**Config key:** `runtime_config["conflict_warning"]`

When the CRT pipeline detects contradicting facts about a topic, it can attach a layperson-friendly explanation that the answer might be uncertain.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `enabled` | bool | `true` | Show conflict warnings in responses |

### Example

If the user previously said "I work at Google" and later "I work at Meta", a query about their employer might return:

> I have some conflicting information about your employer — you've mentioned both Google and Meta. Could you clarify which is current?

The warning is generated by the contradiction detection pipeline (NLI or rule-based) and injected into the response only when conflicting evidence exists and confidence is below the threshold.

## Provenance Footers

**Config key:** `runtime_config["provenance"]`

When enabled, responses can include a short footer explaining where the information came from — personal memory, cloud verification, or general knowledge.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `enabled` | bool | `true` | Add provenance notes to answers |
| `world_check.enabled` | bool | `false` | Cross-check against public facts |
| `world_check.max_tokens` | int | `140` | Token budget for world check |

### World Check

The optional world check runs a second-pass sanity check against widely-known public facts. This is intentionally conservative — it produces warnings ("this might not match public records"), not truth-picking. Disabled by default because it adds latency and cloud cost.

## Response Variation

**Config key:** `runtime_config["response_variation"]`

Prevents the agent from giving identical responses when the same question is repeated. When the user asks "what's my name?" three times, each response uses a different template.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `enabled` | bool | `true` | Enable response variation |
| `window_size` | int | `5` | Recent messages to check for repetition |
| `slot_queries_only` | bool | `true` | Only vary slot-based queries |

### Slot Templates

Each slot type has 3-5 alternative phrasings:

**name:** `"{value}"`, `"Your name is {value}."`, `"Still {value}!"`, `"You're {value}."`, `"{value}, as you told me."`

**employer:** `"{value}"`, `"You work at {value}."`, `"Still {value}!"`, `"{value}, according to what you've told me."`

**default:** `"{value}"`, `"That would be {value}."`, `"{value}, as I recall."`

## Settings UI Status

The Settings page (Behavior tab) provides controls for:
- Greeting enable/disable and style selector
- Conflict warning toggle
- Provenance footer toggle with world check sub-toggle

> **Note:** These UI controls are currently **stubbed**. Values save to `user_settings` but the backend reads from `crt_runtime_config.json` / `runtime_config.py` defaults. To wire them, each service needs to check `auth.get_user_setting()` with fallback to the runtime config value. See [Settings Page](SETTINGS.md) for details.

## Customization via Runtime Config

All of these systems can be customized by editing `crt_runtime_config.json` in the project root. The file is deep-merged over defaults, so you only need to include the keys you want to change:

```json
{
  "greeting": {
    "style": "simple",
    "templates": {
      "new_user": "Hi there! How can I help?"
    }
  },
  "conflict_warning": {
    "enabled": false
  },
  "provenance": {
    "enabled": true,
    "world_check": { "enabled": true }
  }
}
```
