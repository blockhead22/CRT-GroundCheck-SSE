The Feeling

Why This Is Not Just Memory

You started with a simple frustration: if an AI is supposed to grow with a person, why does memory feel so brittle? Why does it overwrite, summarize away the important parts, or confidently repeat the wrong thing?

That question is not dumb. It points at the load-bearing problem: long-term AI usefulness depends on memory that survives change. Not just more storage. Not just bigger context. The system has to know what changed, what used to be true, what is still uncertain, and what it is allowed to say now.

The Core Claim

The Thing We Are Trying To Prove

meaningful memory = current facts + prior facts + contradictions + source / authority + trust / confidence + policy constraints + response rules
The current proof track is not trying to define all human meaning. It is testing whether these meaning-bearing layers can be preserved under compression and then used to govern future answers.

The sharp version: CRT should not just retrieve old text. It should compile messy memory history into governed state: what is current, what is superseded, what is contested, what is provisional, and what should constrain speech or action.

The Pipeline

How The System Wants To Work

Step 01
User says something
The input might be a fact, correction, preference, social observation, policy, question, or noise. CRT should not treat all of those equally.
Step 02
Extract meaning-bearing structure
Current code mostly uses regex-backed slots. That is not the final dream, but it gives the labs a concrete structure to test.
Step 03
Preserve changes instead of overwriting
If "Microsoft" becomes "Amazon", the answer should use Amazon. But Microsoft should not disappear. It becomes history and contradiction context.
Step 04
Compress without flattening meaning
The real test is whether compression keeps the layers that matter: current value, prior value, contradiction, authority, policy, and response behavior.
Step 05
Govern future answers
The model should speak through the governed state. It should not answer provisional data as confirmed truth, and it should not ignore locked policy.
Why Care

The Local AI Angle

Wrong Fight

A local model is usually not going to beat a premium frontier model on raw general reasoning. That is not the claim to bet the project on.

Better Fight

A local model with memory, tools, files, policies, and governed continuity might beat a stronger stateless model on long-term personal-agent tasks.

The practical thesis is: substrate quality can compensate for model size on continuity-heavy work. If the local assistant knows your files, your repo, your policies, your corrections, your old mistakes, and what information is provisional, then it can become useful in a way a generic stateless chat session cannot.

The Honest Part

What This Does Not Prove Yet

This is not a breakthrough claim yet.

The current labs are small. Some inputs are still hand-authored. Slot extraction is mostly regex-backed. The force-push policy path is intentionally narrow. The Ollama comparison is useful, but it is not a full benchmark against all possible RAG systems.

Not Proven

  • general dynamic slot discovery
  • arbitrary policy understanding
  • large-scale real-world memory stability
  • premium model comparison
  • full product/plugin readiness

Actually Supported

  • tested contradiction preservation
  • tested authority boundaries
  • tested answer behavior bridge
  • tested CRT vs naive structural baselines
  • tested raw retrieval failure modes
Why This Dork Should Care

The Non-Hype Reason To Keep Going

You should care if the thing that originally bothered you still bothers you: current AI systems often do not have a durable self, a durable relationship, or a durable memory contract. They can sound coherent while quietly losing the shape of what happened.

CRT is interesting because it is trying to make memory accountable. If the system says something about you, there should be a structure behind that answer: source, authority, current value, prior value, contradiction status, and response rule.

That is not fodder. It is just not finished. The honest path is to keep turning the intuition into tests that can embarrass the system when it is wrong.

Breakthrough Criteria

What Would Actually Count As A Breakthrough?

A breakthrough here does not mean one impressive demo. It means CRT keeps winning after the tests get larger, fairer, harder, and less hand-held. These are the milestones that would make the work harder to dismiss.

Engineering Breakthrough

CRT reliably beats raw RAG, latest-only slots, and naive summaries on a larger adversarial memory pack covering corrections, policy, uncertainty, and history.

Path: expand 5 cases to 30+ judged probes.

Compression Breakthrough

A compact meaning state preserves the important invariants after long noisy histories: current value, prior value, contradiction, authority, confidence, and response rule.

Path: stress memory under token and record budgets.

Local Substrate Breakthrough

A smaller local model plus CRT outperforms the same model with raw retrieval, and possibly a stronger stateless model, on continuity-heavy personal-agent tasks.

Path: local model vs local+RAG vs local+CRT lab.

Research Breakthrough

Ablations show that contradiction, authority, and policy are not decorative metadata. Removing them causes measurable answer failures.

Path: remove one layer at a time and score failures.

Architecture Breakthrough

The pipeline stops being a bundle of special cases and becomes a clean MeaningState compiler that many extractors, retrievers, and models can use.

Path: refactor only after tests pin behavior.

Product Breakthrough

A user can inspect why the assistant answered something, see what changed, and correct it without the system silently overwriting or flattening memory.

Path: explainable memory graph and repair UI.

What would not count.

A single local model failure, a pretty explanation page, or a hand-coded answer path is not enough. The project becomes defensible when the same governed-memory advantage survives broader tests and fairer baselines.

Roadmap

What Comes Next

Expand the adversarial memory pack

Move from five cases to 20 or 30. Include corrections, social/provisional claims, model-generated contamination, history questions, denial attempts, and policy constraints.

Harden the plain-RAG baseline

Make the raw retrieval comparison fairer with better retrieval, stable prompts, local-model runs, and deterministic judging.

Make policy memory first-class

Replace the narrow force-push special case with structured action-policy memory that can be stored, replayed, retrieved, and enforced.

Create a claim matrix report

Map each public claim to code paths, tests, result files, caveats, and the next validation needed.

Build the local substrate advantage lab

Compare local model alone, local model plus plain RAG, local model plus CRT, and possibly a premium stateless model on continuity-governed tasks.

Then revisit dynamic slot identification

Once the governed-state architecture proves useful, better slot discovery becomes a multiplier instead of a distraction.

Decision Rule

How We Know Whether This Has Legs

Keep going if: CRT keeps beating raw retrieval, naive summary, and slot-only baselines on contradiction, authority, policy, and continuity tasks as the test pack gets larger and fairer.

Reframe if the advantage disappears.

If better baselines catch up, or CRT only wins through brittle hand-coded special cases, then the project should narrow its claims or pivot. That would not mean the work was wasted. It would mean the harness did its job.
