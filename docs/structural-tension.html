Section 1

The Problem with Contradiction Detection

Current approaches to contradiction detection in memory systems share a common architecture: take two memory entries, send them to a language model, and ask “do these contradict?” This framing is natural — it mirrors how a human might evaluate the relationship. But it fails in practice for three reasons that are structural, not incidental.

Failure Mode 1 Small models say YES to everything When primed with a claim and asked whether a second claim contradicts it, models under 7B parameters exhibit a strong affirmative bias. The framing of the question — “do these contradict?” — activates pattern-matching on “different claims about the same topic,” which the model reliably classifies as contradiction regardless of actual semantic relationship. In our experiments, a 3B parameter model scored 40% accuracy by saying YES to nearly every pair.
Failure Mode 2 Large models are prohibitively expensive An epistemic memory system with 500+ memories that adds new entries continuously cannot afford to run pairwise LLM comparisons on every write. At \(n\) memories, write-time contradiction checking is \(O(n)\) LLM calls per insertion — and continuous background monitoring is \(O(n^2)\) per sweep. Even with embedding-based pre-filtering, the cost of cloud inference for contradiction judgment makes continuous governance infeasible for personal or edge-deployed systems.
Failure Mode 3 The question itself is wrong Two memories about the same topic are not necessarily contradictory. “Nick is a developer” and “Nick works on AI” are compatible. “Nick lives in Wisconsin” and “Nick lives in Milwaukee, Wisconsin” is a refinement. “Nick was a student” and “Nick is a developer” is temporal evolution. The binary question “contradiction: yes/no?” collapses a rich space of belief relationships into a single bit. The real question is: what is the relationship between these beliefs?
Core Thesis
Tension is measurable. Models are not required.
The relationship between two beliefs can be determined by structural measurement alone — slot overlap, value divergence, embedding proximity, trust differential, and temporal alignment. No language model inference is needed.
Section 2

Tension as a Measurable Quantity

We formalize the notion of tension between two beliefs. Rather than asking a model for a judgment, we decompose the comparison into five independently computable signals and combine them into a deterministic tension score.

Definition 2.1 — Memory Entry

Let a memory entry \(M\) be a tuple:

\[ M = (t, \tau, \sigma, T, S) \]

where \(t\) is the text content, \(\tau \in [0, 1]\) is the trust score, \(\sigma\) is the source identifier, \(T\) is the timestamp with temporal status \(\theta \in \{\text{past}, \text{active}, \text{future}, \text{potential}\}\), and \(S = \{(k_i, v_i)\}_{i=1}^{m}\) is the set of extracted fact slots (key-value pairs).

Definition 2.2 — Five Tension Signals

Given two memory entries \(M_a\) and \(M_b\), we define five signals:

1. Topic Proximity — Cosine similarity of embedding vectors:

\[ \text{prox}(M_a, M_b) = \cos\bigl(\text{embed}(t_a),\; \text{embed}(t_b)\bigr) \]

2. Slot Overlap — The set of shared semantic slot keys:

\[ \Omega = \{ k \mid k \in \text{keys}(S_a) \cap \text{keys}(S_b) \} \]

3. Value Divergence — For each shared slot \(k \in \Omega\), a normalized comparison of values:

\[ \delta(k) = \begin{cases} 0 & \text{if } v_a(k) = v_b(k) \\ 0.5 & \text{if } v_a(k) \subset v_b(k) \text{ or } v_b(k) \subset v_a(k) \\ 1 & \text{otherwise} \end{cases} \]

Aggregate divergence:

\[ D(M_a, M_b) = \frac{1}{|\Omega|} \sum_{k \in \Omega} \delta(k) \]

4. Trust Differential — The absolute difference in trust scores:

\[ \Delta\tau = |\tau_a - \tau_b| \]

5. Temporal Alignment — Whether temporal statuses explain the divergence:

\[ \alpha(\theta_a, \theta_b) = \begin{cases} 1 & \text{if } \theta_a \neq \theta_b \text{ and both are valid temporal states} \\ 0 & \text{otherwise} \end{cases} \]
Definition 2.3 — Tension Score

The tension score \(\mathcal{T}(M_a, M_b)\) is a deterministic function of the five signals:

\[ \mathcal{T}(M_a, M_b) = \text{prox}(M_a, M_b) \cdot D(M_a, M_b) \cdot (1 - \alpha(\theta_a, \theta_b)) \]

Intuitively: tension is high when two memories are topically close (high proximity), have conflicting values in shared slots (high divergence), and the difference is not explained by temporal evolution (low temporal alignment). The trust differential \(\Delta\tau\) and slot overlap count \(|\Omega|\) serve as confidence modifiers that determine disposition (TENSION vs. CONFLICT) rather than raw tension magnitude.

Key property: The tension score is fully deterministic and computable in \(O(|S|)\) time after the one-time embedding computation. No model inference is required at comparison time. At approximately 0.2 seconds per pair on consumer hardware, it is suitable for continuous background monitoring.

Computational Complexity

ANALYSIS · PER-PAIR COST

Embedding lookup: \(O(1)\) (pre-computed at write time). Cosine similarity: \(O(d)\) where \(d\) is embedding dimension. Slot comparison: \(O(|S_a| + |S_b|)\) for intersection, \(O(|\Omega|)\) for divergence. Trust and temporal checks: \(O(1)\). Total: dominated by embedding dimension, which is a fixed constant (typically 384 or 768). Zero model calls. Zero cloud dependency. Zero cost per comparison.

Section 3

Seven Relationship Types

The tension measurement, combined with its component signals, classifies belief pairs into seven distinct relationship types. Each type has formal conditions and a prescribed action. This replaces the binary “contradiction: yes/no” with a rich taxonomy of belief interactions.

DUPLICATE

Same slot, same value, high similarity

Formal conditions: \(|\Omega| \geq 1\), \(D = 0\), \(\text{prox} > 0.85\). The entries encode the same fact, possibly with different phrasing.

Example: “Nick is a developer” vs. “Nick works as a developer” — same occupation slot, same value.
Action: merge (keep higher trust)
REFINEMENT

Same slot, subset value

Formal conditions: \(|\Omega| \geq 1\), at least one shared slot has \(v_a(k) \subset v_b(k)\) or vice versa (\(\delta = 0.5\)), \(\text{prox} > 0.75\). One entry is a more specific version of the other.

Example: “Nick lives in Wisconsin” vs. “Nick lives in Milwaukee, Wisconsin” — location slot, subset relationship.
Action: keep more specific, deprecate general
COMPATIBLE

Same topic, different slots or temporal evolution

Formal conditions: \(\text{prox} > 0.6\) but either \(|\Omega| = 0\) (different fact slots) or \(\alpha = 1\) (temporal difference explains value change). No actual disagreement exists.

Example: “Nick is a developer” vs. “Nick works on AI” — occupation slot vs. project/domain slot. Different facets of the same person.
Action: keep both
TENSION

Same slot, different value, weak confidence signals

Formal conditions: \(|\Omega| \geq 1\), \(D > 0.5\), \(\alpha = 0\), but \(\Delta\tau < 0.2\) and \(|\Omega| \leq 1\). There is a genuine disagreement, but the evidence is not strong enough to resolve automatically.

Example: “Nick prefers Python” vs. “Nick prefers TypeScript” — preference slot, different values, similar trust. Could reflect genuine change or context-dependent preference.
Action: escalate (hold as tension, do not resolve)
CONFLICT

Same slot, different value, strong confidence signals

Formal conditions: \(|\Omega| \geq 1\), \(D > 0.5\), \(\alpha = 0\), and either \(\Delta\tau > 0.3\) or \(|\Omega| \geq 2\). Multiple overlapping slots disagree, or one entry has substantially higher trust. Clear winner exists.

Example: “Nick works at Google” (\(\tau = 0.3\)) vs. “Nick is a freelance developer” (\(\tau = 0.8\)) — occupation slot, different values, large trust gap.
Action: deprecate weaker, boost winner
UNRELATED

Low similarity, no shared slots

Formal conditions: \(\text{prox} < 0.5\), \(|\Omega| = 0\). The memories are about different topics entirely. No meaningful comparison is possible.

Example: “Nick likes coffee” vs. “The meeting is on Thursday” — no topical connection, no shared slots.
Action: no action
DECAYED

Low trust, observation source

Formal conditions: \(\tau < 0.3\), \(\sigma = \text{observation}\). The entry was inferred rather than stated, and has accumulated low trust through repeated non-confirmation or contradiction. Regardless of its relationship to other entries, it warrants review.

Example: “Nick might be interested in gardening” (\(\tau = 0.15\), source: observation) — a weak inference that never gained supporting evidence.
Action: flag for review or removal
Coverage: These seven types partition the space of belief-pair interactions. Every pair maps to exactly one type through the decision tree: first check proximity threshold (UNRELATED), then check slot overlap and divergence, then check temporal alignment (COMPATIBLE), then check confidence signals (TENSION vs. CONFLICT), and finally check trust decay (DECAYED). The mapping is deterministic — no model judgment, no ambiguity.
Section 4

The Resonance Interpretation

The name “Cognitive Resonance Theory” has always implied a physical metaphor: beliefs resonate with each other, creating patterns of reinforcement and interference. The structural tension framework gives this metaphor a precise, computable interpretation.

Resonance Principle
Resonance is the interference pattern between beliefs.
The tension score measures the amplitude and character of this interference. It is not a metaphor — it is a measurement.
Constructive Interference High similarity + same slot + same value Two beliefs reinforce each other. The signals are in phase: they occupy the same semantic space and agree on the value. This is the DUPLICATE or REFINEMENT relationship. In wave terms, the amplitudes add. In belief terms, mutual confirmation increases trust in both entries. The system becomes more confident.
Destructive Interference High similarity + same slot + different value Two beliefs cancel each other. The signals are out of phase: they occupy the same semantic space but disagree on the value. This is the TENSION or CONFLICT relationship. In wave terms, the amplitudes subtract. In belief terms, the system’s confidence in the contested fact drops. One must yield, or both must be held in tension.
Orthogonal Modes Moderate similarity + different slots Two beliefs vibrate in independent modes. They concern the same topic but different facets — like two eigenmodes of the same physical system that do not exchange energy. This is the COMPATIBLE relationship. In belief terms, both can coexist because they occupy non-overlapping dimensions of the fact space.
Theorem 4.1 — Resonance Stability

A belief graph \(G = (V, E)\) is resonance-stable if and only if for every edge \((M_a, M_b) \in E\):

\[ \mathcal{T}(M_a, M_b) < \epsilon \quad \text{or} \quad \text{rel}(M_a, M_b) \in \{\text{TENSION}\} \]

That is, every belief pair is either below the tension threshold (resolved) or explicitly held as tension (acknowledged). A resonance-stable graph has no unacknowledged conflicts — every interference pattern has been measured and classified.

The breathing loop (Section 8) continuously drives the belief graph toward resonance stability. Each cycle measures the interference pattern across all recently-changed neighborhoods and takes action on any pair that exceeds the tension threshold. The system converges not by resolving all contradictions, but by acknowledging them — converting unclassified interference into typed relationships.

Connection to held contradiction: The TENSION relationship type is precisely the “held contradiction” theorized in earlier CRT work. Some contradictions should not be resolved — they represent genuine uncertainty, evolving states, or context-dependent truths. The tension meter identifies these and holds them explicitly, rather than forcing premature resolution. Contradiction as signal, not as error.

Section 6

Why LLMs Fail at This Task

The 40% accuracy of the 3B model is not a prompting failure. We tested multiple prompt formats, including chain-of-thought, few-shot examples, and explicit definitions of each relationship type. Accuracy varied between 35% and 43% across formats. The failure is structural: the task requires a capability that small autoregressive models do not reliably possess.

The Completion Trap

When given the prompt “Do these two memories contradict each other?” followed by two claims, the model performs next-token prediction in a context that has been primed for “contradiction detection.” The statistical pattern is clear: the word “contradict” in the prompt activates attention patterns associated with disagreement, making YES the high-probability completion regardless of the actual semantic relationship.

Failure Pattern 1 Different claims conflated with contradictory claims “Nick is a developer” vs. “Nick works on AI” → the model sees two different statements about the same entity and classifies this as contradiction. The model cannot distinguish “different fact about the same topic” from “conflicting fact about the same topic.” These are structurally distinct relationships (COMPATIBLE vs. CONFLICT), but the model compresses them into a single pattern: “two claims, same entity, different content = contradiction.”
Failure Pattern 2 Refinement misclassified as contradiction “Nick lives in Wisconsin” vs. “Nick lives in Milwaukee, Wisconsin” → the model sees different location strings and says CONTRADICTION. It cannot perform the subset check that reveals Milwaukee, Wisconsin as a refinement of Wisconsin. This requires structured comparison — checking whether one value contains or specializes the other — which is a string operation, not a language understanding task.
Failure Pattern 3 Temporal evolution invisible without metadata “Nick was a student” vs. “Nick is a developer” → without access to temporal metadata, the model must infer from tense alone that these describe different life stages. Small models frequently miss this inference. The structural approach uses explicit temporal status fields (\(\theta_a = \text{past}\), \(\theta_b = \text{active}\)) to classify this as COMPATIBLE without any inference at all.
Diagnosis
The model completes based on framing. It does not reason about relationships.
This is a fundamental capability limit of small autoregressive models on structured comparison tasks, not a prompting failure. The fix is not a better prompt — it is removing the model from the judgment loop entirely.
Implication for system design: This finding suggests that any epistemic memory system relying on small local models for continuous contradiction monitoring will converge to a state where most belief pairs are flagged as contradictions. The system becomes noise-dominated. Structural measurement avoids this failure mode entirely by never entering the completion trap.
Section 7

Slot Extraction as Semantic Decomposition

The structural tension approach depends critically on the quality of fact slot extraction. The CRT system maintains a taxonomy of 28+ slot types that decompose natural-language memories into structured key-value pairs. This decomposition is the foundation of measurement-based governance.

Slot Taxonomy

Category Slot Types Example
Identity name, alias, age, birthday “Nick Block” → name: "Nick Block"
Location location, city, state, country “lives in Milwaukee” → location: "Milwaukee"
Occupation occupation, employer, role “freelance developer” → occupation: "developer", employment_type: "freelance"
Skills skill, language, framework “works with Python” → skill: "Python"
Preferences preference, favorite_food, favorite_music, etc. “prefers dark mode” → preference: "dark mode"
Relationships relationship, family, pet “has a dog named Max” → pet: "Max"
Temporal temporal_status: past / active / future / potential “used to live in Chicago” → location: "Chicago", temporal_status: "past"

The slot taxonomy serves two functions in the tension framework:

Function 1 Slot overlap defines the comparison axis When two memories share a slot key (e.g., both have occupation), we know exactly what to compare: the slot values. This eliminates the ambiguity that plagues LLM-based comparison. The model must figure out what the memories are about and how they relate. The slots tell us both: the key defines the dimension, and the value defines the position along that dimension.
Function 2 Embedding similarity handles the residual When slots do not overlap, embedding similarity determines whether the memories are even about the same topic. A pair with no shared slots and low embedding similarity is UNRELATED. A pair with no shared slots but high embedding similarity is COMPATIBLE — they describe different facets of the same subject. The slots handle the structured case; embeddings handle the unstructured case. Together they cover the full space.
Connection to BDG leaf questions: The slot decomposition follows the same principle as the Belief Dependency Graph’s leaf nodes. A high-level belief (“I know Nick well”) decomposes into specific factual claims (occupation, location, preferences). Slots ARE the leaf-level decomposition — the atomic units where truth values can be compared. The tension meter operates at this leaf level, measuring interference between atomic facts rather than between vague high-level beliefs.

Property 8.1 — Convergence

The breathing loop is a contraction mapping on the space of unclassified belief relationships. Each cycle:

  1. Identifies all pairs involving recently-changed memories
  2. Classifies each pair into one of seven types
  3. Takes action on DUPLICATE, REFINEMENT, and CONFLICT pairs (reducing the number of unresolved pairs)
  4. Explicitly marks TENSION pairs (converting unclassified interference to acknowledged tension)

Since actions in step 3 reduce the number of entries (merges, deprecations) and step 4 converts unknown states to known states, the number of unclassified pairs monotonically decreases. The system converges to resonance stability (Theorem 4.1) in finite cycles.

Breathing Loop Performance

PRODUCTION · MEASURED CHARACTERISTICS

Cycle time: 30 seconds. Per-pair latency: ~0.2s. Typical neighbors per changed memory: 3–8. Worst-case cycle cost: 8 pairs × 0.2s = 1.6s of computation per cycle. LLM calls: zero. Cloud dependency: zero. The system continuously tightens its belief state using only local computation — CPU, embeddings, and slot comparison. This is the “breathing loop” theorized in prior sessions, implemented as a tension measurement cycle.

Section 9

Integration Architecture

Structural tension integrates into the CRT pipeline at three distinct points, each serving a different governance function. The tension meter is the same module in all three contexts — only the trigger and the action differ.

Integration Point 1 Write Path: Pre-Storage Check Before a new memory is committed to storage, the tension meter runs against all memories sharing at least one slot key with the incoming entry. This catches duplicates before they enter the system (preventing the “500 memories saying the same thing” failure mode) and surfaces conflicts at write time when the user’s statement is still in context. Write-path tension checking adds ~0.2s per matched neighbor to the storage pipeline — negligible compared to the embedding computation that already occurs.
Integration Point 2 Consolidation: NLI Pre-Filter The consolidation pass runs periodically to clean the memory store. Previously, this required NLI (Natural Language Inference) calls to a cloud model for every candidate pair — expensive and slow. Structural tension serves as a pre-filter: only pairs classified as TENSION or CONFLICT are forwarded to the NLI stage. In production, this reduces cloud NLI calls by 60–80%, because the majority of pairs are COMPATIBLE, UNRELATED, or DUPLICATE (all resolvable without NLI).
Integration Point 3 Heartbeat: Continuous Monitoring The breathing loop (Section 8) runs the tension meter every 30 seconds on recently-changed memory neighborhoods. This is the actual continuous self-governance mechanism — the system monitors its own belief coherence without any user interaction, any LLM inference, or any cloud dependency. The heartbeat is the nervous system; the tension meter is the sensory organ.

Connection to Prior CRT Work

Structural tension is not an isolated technique. It completes a loop that connects four major CRT theories, providing the measurement mechanism that each theory assumed but did not specify.

Connection 1 Contradiction-as-Drive Theory The contradiction-as-drive theory proposes that unresolved contradictions generate a “drive signal” that motivates the system to act — to gather information, to re-evaluate beliefs, to seek resolution. The tension score IS this drive signal. A high tension score between two beliefs is a measurable quantity that can be thresholded, ranked, and routed. The system can prioritize which tensions to address based on magnitude, age, and impact on downstream beliefs. Drive is no longer metaphorical — it is a number.
Connection 2 Held Contradiction The held contradiction theory distinguishes three states for contradictions: resolvable, held, and evolving. The TENSION relationship type maps directly to the “held” state — genuine disagreement that should not be prematurely resolved. The tension meter provides the classification mechanism: CONFLICT is resolvable (clear winner), TENSION is held (ambiguous), and COMPATIBLE-with-temporal-alignment is evolving. The theory now has a computable implementation.
Connection 3 Belief Backpropagation Belief backpropagation requires knowing WHERE in the belief graph an error occurred before propagating corrections backward. Structural tension identifies the error site: a CONFLICT relationship means one belief is wrong, and the trust differential indicates which one. The tension meter provides the error signal; backpropagation provides the correction mechanism. Together they form a complete error detection and correction loop: measure → locate → propagate → adjust.
Connection 4 Cascade Complexity The cascade complexity paper proves that trust changes propagate through the Belief Dependency Graph following cascade rules with bounded depth and damped influence. Structural tension defines WHAT triggers a cascade: a CONFLICT resolution that changes a trust score initiates a cascade through all beliefs that depend on the affected entry. The tension meter is the trigger; the BDG is the propagation medium; the cascade rules determine the extent. Tension propagation through the BDG follows exactly the cascade dynamics described in the formal model.
Unifying Principle
Measure → Propagate → Govern → Measure
The tension meter completes the epistemic governance loop. Measurement identifies interference. Backpropagation distributes the correction. Cascade rules bound the impact. The breathing loop re-measures. The cycle continues. Each component was developed independently; structural tension reveals that they form a single coherent system.
The Complete Governance Loop

The four CRT theories connect in a cycle:

\[ \underbrace{\mathcal{T}(M_a, M_b)}_{\text{Tension Meter}} \;\xrightarrow{\text{error signal}}\; \underbrace{\text{BackProp}(G, M_{\text{wrong}})}_{\text{Belief Backpropagation}} \;\xrightarrow{\text{trust updates}}\; \underbrace{\text{Cascade}(G, \Delta\tau)}_{\text{Cascade Complexity}} \;\xrightarrow{\text{changed beliefs}}\; \underbrace{\text{Breathe}(G)}_{\text{Breathing Loop}} \;\xrightarrow{\text{re-measure}}\; \mathcal{T} \]

Each arrow is a computable operation. Each box is an implemented module. The cycle runs continuously without human intervention and without language model inference. This is autonomous epistemic self-governance.

Section 11

Conclusion

This paper has argued for a fundamental reframing of contradiction detection in epistemic memory systems. The standard approach — asking a language model to judge the relationship between two memories — fails for reasons that are structural, not incidental. Small models exhibit affirmative bias that makes them unreliable classifiers. Large models are too expensive for continuous monitoring. And the binary question itself (“do these contradict?”) discards the rich taxonomy of belief relationships that a governance system needs.

The alternative is measurement. Five signals — topic proximity, slot overlap, value divergence, trust differential, and temporal alignment — combine into a deterministic tension score that classifies belief pairs into seven relationship types with 88% accuracy. No language model is needed. No cloud dependency exists. The cost per comparison is effectively zero.

Finding 1 Structural measurement outperforms LLM judgment 88% accuracy with zero LLM calls vs. 40% accuracy with one LLM call per pair. The gap is not marginal — it is a 2.2x improvement. And it widens further when considering cost, latency, and scalability.
Finding 2 Adding LLMs makes it worse, not better The hybrid approach (structural + LLM override) scored 38% — lower than either pure approach alone. The LLM’s affirmative bias contaminates structurally correct classifications. The optimal LLM contribution to this task is zero.
Finding 3 Continuous self-governance becomes feasible At ~0.2s per pair with zero cost, the breathing loop can monitor belief coherence every 30 seconds indefinitely. This transforms governance from a periodic batch operation into a continuous background process — the epistemic equivalent of a heartbeat.
Finding 4 Tension completes the CRT governance loop Structural tension provides the measurement mechanism that connects contradiction-as-drive, held contradiction, belief backpropagation, and cascade complexity into a single coherent system. Measure, propagate, govern, re-measure. The loop is closed.
Conclusion
Tension is measurable. The resonance is computable. The breathing loop needs a meter, not a model.
The “resonance” in Cognitive Resonance Theory has a precise, implementable definition: it is the interference pattern between beliefs, measured by structural tension, governed by a continuous breathing loop, and propagated through the Belief Dependency Graph. Every component is built. Every measurement is deterministic. The system governs itself.
