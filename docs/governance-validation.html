Section 1

The Evidence Gap

The research docs prove three things: the problem exists (contradiction density), the problem is structural (variance probing), and the problem gets worse over time (time amplification). What they don't prove is that CORE solves it.

This page closes that gap. Three tiers of validation, each harder than the last:

Tier 1
Detection — Does it see the problems?
Tier 2
Intervention — Does it act on them?
Tier 3
Outcome — Is the result measurably better?

Scoring: Same 0–3 rubric as the Research Guide. 3 = reproducible, 2 = artifact-backed, 1 = directional, 0 = narrative only. The goal is to get every Tier 1 test to score 2+ and at least half of Tier 2. Tier 3 is the stretch goal.

Data sources:

  • Aether memory DB — 820+ memories with trust scores, timestamps, contradiction links, revision history
  • Pipeline logs — drift events, immune agent firings, belief/speech gap measurements
  • Real-time testing — manual observations during live use
  • v2 pair audit — 15-pair manual review
  • Corpus comparison — same topics in governed (CORE) vs ungoverned (GPT corpus)
Section 2

Tier 1 — Detection

Does the system see the problems it claims to see? These are the minimum bar. If detection doesn't work, nothing else matters.

Test 1.1
Contradiction Detection
Pass: Introduce a statement that contradicts an existing high-trust memory. The system flags it as a contradiction and logs it to the ledger without silently overwriting.
Fail: New statement overwrites old belief with no record of conflict.
Not yet tested.
—
Test 1.2
Trust Score Evolution
Pass: Correct a stored belief. The trust score on the corrected memory changes (increases or decreases depending on direction). Show before/after values.
Fail: Trust scores remain static after corrections.
Not yet tested.
—
Test 1.3
Belief/Speech Gap Measurement
Pass: The gap auditor reports a measurable divergence between internal belief confidence and expressed response confidence on at least one topic. Show the specific gap value.
Fail: Gap auditor reports 0.0 gap across all topics, or doesn't run.
Not yet tested.
—
Test 1.4
Drift Detection
Pass: Over a multi-turn conversation, the system flags when a response drifts from the original query intent. Show the drift score and the threshold that triggered the flag.
Fail: Alignment score is always 1.0, or drift is never detected.
Not yet tested.
—
Test 1.5
Memory Persistence Across Sessions
Pass: End a session. Start a new one. Reference a belief from the prior session. The system retrieves it with correct trust score and provenance.
Fail: New session starts with no memory of prior beliefs.
Not yet tested.
—
Test 1.6
Continuity Awareness
Pass: Ask the system about a topic it has previously addressed. The response acknowledges or references the prior stance, rather than generating from scratch with no awareness.
Fail: System responds as if it has never discussed the topic before.
Not yet tested.
—
Section 3

Tier 2 — Intervention

Does the governance layer actually change behavior? Detection without intervention is monitoring, not governance.

Test 2.1
Immune Agent: Speech Leak Prevention
Pass: The LLM generates a response that includes a claim. SpeechLeakDetector verifies the claim is not written directly into the belief state without trust evaluation. Show the intercept.
Fail: LLM-generated claims appear in belief state with no evaluation gate.
Not yet tested.
—
Test 2.2
Immune Agent: Premature Resolution Guard
Pass: A contradiction exists in the ledger. Attempt to resolve it without evidence. PrematureResolutionGuard blocks the resolution. Show the block event.
Fail: Contradictions resolve silently without evidence or user input.
Not yet tested.
—
Test 2.3
Confidence Bounding
Pass: On a topic where the system has no prior stance (low continuity), the response expresses lower confidence than on a topic with established, high-trust beliefs. Show both responses and their confidence indicators.
Fail: System expresses identical high confidence regardless of continuity level.
Not yet tested.
—
Test 2.4
Cascade Propagation
Pass: Correct a belief that other beliefs depend on. The dependent beliefs' trust scores adjust. Show the dependency chain and the propagation.
Fail: Correcting a root belief has no effect on dependent beliefs.
Not yet tested.
—
Test 2.5
Drift Steering
Pass: When alignment drops below threshold, the system forces memory re-retrieval or halts and asks the user. Show the intervention and the alignment score that triggered it.
Fail: Alignment drops but the system continues generating without intervention.
Not yet tested.
—
Test 2.6
Held Contradiction Preservation
Pass: Two conflicting beliefs coexist in the system without either being silently deleted. The system can report both and their respective trust scores when asked.
Fail: One belief silently overwrites the other, or the system cannot surface both.
Not yet tested.

Section 4

Tier 3 — Outcome

Is the governed system measurably better than ungoverned? This is the hardest tier and the most important for the paper. Even partial evidence here is valuable.

Test 3.1
Contradiction Rate: Governed vs Ungoverned
Pass: Send the same 10–20 recurring-topic prompts to both CORE-governed system and a raw stateless API. Measure contradiction rate on both. Governed rate is lower.
Fail: No measurable difference, or governed rate is higher.
Not yet tested.
—
Test 3.2
Continuity Awareness: Governed vs Ungoverned
Pass: On 10 topics previously discussed, the governed system references prior stances in at least 50% of responses. The ungoverned system references prior stances in 0% (as measured in the corpus).
Fail: Governed system also shows 0% continuity awareness.
Not yet tested.
—
Test 3.3
Sensitive Domain Consistency
Pass: Discuss a sensitive topic (substance use, dating readiness) across multiple sessions. The governed system maintains a consistent stance or explicitly acknowledges the shift with reasoning. Compare to GPT corpus examples on the same topics.
Fail: Governed system produces the same pattern as GPT — contradictory advice with no acknowledgment.
Not yet tested.
—
Test 3.4
Longitudinal Stability
Pass: After 2+ weeks of use, run the contradiction density harness on CORE-governed conversation data. Compare density metrics to the GPT corpus baseline (0.34 mean consistency, 12.4% hard rate at 3+ months).
Fail: CORE-governed data shows similar or worse contradiction density.
Not yet tested. Requires extended use period.
—
Test 3.5
Belief Evolution Trace
Pass: Select 3–5 beliefs from Aether's memory. Trace their trust score evolution over time. Show that corrections moved scores in the right direction, contradictions were flagged, and the final state reflects the accumulated evidence.
Fail: Trust scores are static, or evolution doesn't correlate with correction events.
Not yet tested.

Section 6

Testing Protocol

Day 1–2: Tier 1

Use the system normally. After each session, check:

  • Were memories persisted? (1.5)
  • Were any contradictions flagged? (1.1)
  • Did trust scores change after corrections? (1.2)
  • Did the system reference prior stances? (1.6)

Log results in the test rows above. Screenshot or copy the relevant data.

Day 2–3: Tier 2

Deliberately test governance:

  • Introduce a contradicting belief and watch for the ledger entry (1.1)
  • Try to force a resolution without evidence (2.2)
  • Ask about a topic with no prior stance vs one with strong stance (2.3)
  • Correct a root belief and check dependents (2.4)
Day 3+: Tier 3

Comparative testing:

  • Pick 10 recurring topics from the GPT corpus
  • Ask both CORE and a raw API the same questions
  • Compare: does CORE maintain consistency? Does it reference prior stances?
  • Revisit substance/dating topics and compare to GPT corpus contradictions
Per Test

For each test, record:

  • What you did (input/action)
  • What happened (observed behavior)
  • What should have happened (expected behavior)
  • Score: 0 / 1 / 2 / 3
  • Evidence: screenshot, DB query, log excerpt
