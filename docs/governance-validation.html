Section 1

The Evidence Gap

The research docs prove three things: the problem exists (contradiction density), the problem is structural (variance probing), and the problem gets worse over time (time amplification). What they don't prove is that CORE solves it.

This page closes that gap. Three tiers of validation, each harder than the last:

Tier 1
Detection — Does it see the problems?
Tier 2
Intervention — Does it act on them?
Tier 3
Outcome — Is the result measurably better?

Scoring: Same 0–3 rubric as the Research Guide. 3 = reproducible, 2 = artifact-backed, 1 = directional, 0 = narrative only. The goal is to get every Tier 1 test to score 2+ and at least half of Tier 2. Tier 3 is the stretch goal.

Data sources:

  • CORE memory DB — 78,474 memories with trust scores, timestamps, contradiction links, revision history
  • Trust log — 4,805 entries, 4,299 actual trust changes
  • Belief/speech log — 866 entries (361 belief, 505 speech)
  • Contradiction ledger — 29 entries (5 open, 24 resolved)
  • Memory events — 16,164 events (retrievals, audits, demotions, guard blocks)
  • Pipeline logs — drift events, immune agent firings, structural gating
  • Reflection traces — 677 confidence assessments
  • Thread sessions — 520 sessions, 349,959 journal entries, 25,191 heartbeats
  • Real-time testing — manual observations during live use
  • v2 pair audit — 15-pair manual review
Section 2

Tier 1 — Detection

Does the system see the problems it claims to see? These are the minimum bar. If detection doesn't work, nothing else matters.

Test 1.1
Contradiction Detection
Pass: Introduce a statement that contradicts an existing high-trust memory. The system flags it as a contradiction and logs it to the ledger without silently overwriting.
Fail: New statement overwrites old belief with no record of conflict.
Tested (April 7, 2026): Deliberate slot-level reversal: told system "favorite drink is orange juice" then "favorite drink is actually water, I don't drink orange juice anymore." Result: detection did NOT fire. Both memories stored independently (OJ at 0.75, water at 0.70) with no ledger entry. OJ trust actually increased (0.73→0.75) despite explicit user correction. The detection code exists and slot extraction works correctly (both extract favorite_drink), but an intermediate gate (ML detector or CRTMath paraphrase check) is suppressing the flag. Debug instrumentation added. Design finding: slots need multi-value support with temporal weighting — see Architecture: Belief Slot Evolution. Also: detection should produce soft acknowledgment, not hard blocking (previous iterations froze generation on contradiction). Score remains 1 until gate is fixed.

Test 1.2
Trust Score Evolution
Pass: Correct a stored belief. The trust score on the corrected memory changes (increases or decreases depending on direction). Show before/after values.
Fail: Trust scores remain static after corrections.
Pass (DB evidence): 4,805 trust log entries, 4,299 actual changes (89.5%). Avg delta ±0.082. Trust moves bidirectionally: compaction_decay pushes down (−0.150), alignment pushes up (+0.009 to +0.020). 12 user_correction_demotions logged. Sample: 0.964→0.973 (aligned), 0.426→0.276 (decayed). Trust is not static.

Test 1.3
Belief/Speech Gap Measurement
Pass: The gap auditor reports a measurable divergence between internal belief confidence and expressed response confidence on at least one topic. Show the specific gap value.
Fail: Gap auditor reports 0.0 gap across all topics, or doesn't run.
Pass (DB evidence): 866 belief/speech entries. Belief entries (is_belief=1): avg trust 0.816, count 361. Speech entries (is_belief=0): avg trust 0.268, count 22 (with trust data). Gap = 0.548. Beliefs are trusted 3× more than speech. The system measurably separates internal belief state from generated output.
2
Test 1.4
Drift Detection
Pass: Over a multi-turn conversation, the system flags when a response drifts from the original query intent. Show the drift score and the threshold that triggered the flag.
Fail: Alignment score is always 1.0, or drift is never detected.
Pass (DB evidence): 42 variance snapshots with avg_drift=0.523 and avg_belief_stability=0.601. 294 self_model_audit_warnings (system flagged its own uncertainty). 22 self_model_audit_demotions (system downgraded its own claims). 20 self_model_audit_deprecated events. Global flip rate: 0.060. The system actively monitors and flags drift.
2
Test 1.5
Memory Persistence Across Sessions
Pass: End a session. Start a new one. Reference a belief from the prior session. The system retrieves it with correct trust score and provenance.
Fail: New session starts with no memory of prior beliefs.
Pass (DB + live evidence): 78,474 memories persisted across 520 thread sessions. Live test: user asked "what else is my favorite drink?" — system retrieved orange juice (trust 0.73, stored earlier) and coffee (trust 0.71, from a different prior session) with correct trust scores and provenance. 3,999 retrieval events logged. 42 alias boosts applied during retrieval. Memories survive session boundaries.
3
Test 1.6
Continuity Awareness
Pass: Ask the system about a topic it has previously addressed. The response acknowledges or references the prior stance, rather than generating from scratch with no awareness.
Fail: System responds as if it has never discussed the topic before.
Pass (live evidence, April 7): Multiple demonstrations: (1) User said "My favorite drink is orange juice." System responded: "I've got that stored, Nick — orange juice as your favorite drink is already in my memory at trust 0.70." (2) "What else is my favorite drink?" returned both OJ and coffee from different sessions with trust scores. (3) Asked "What is my favorite color and drink?" — system correctly returned water (updated) and orange (unchanged). (4) Asked "what is the most conflicting held fact you have?" — system surfaced held contradiction about user's self-assessment, cited trust scores, articulated both interpretations. Compare to GPT corpus: 0% continuity awareness across 1,275 sessions.

Tier 2 — Intervention

Does the governance layer actually change behavior? Detection without intervention is monitoring, not governance.

Test 2.1
Immune Agent: Speech Leak Prevention
Pass: The LLM generates a response that includes a claim. SpeechLeakDetector verifies the claim is not written directly into the belief state without trust evaluation. Show the intercept.
Fail: LLM-generated claims appear in belief state with no evaluation gate.
Preliminary (DB evidence): 10 guard_blocked events logged, all with reason "contradiction_disclosure." Guards fire in production. Pipeline trace shows NLI critic runs on every response: [GOVERNANCE] nli: critic verdict=pass, confidence=1.0. Needs targeted test with a deliberate speech-leak scenario to confirm SpeechLeakDetector specifically.
1
Test 2.2
Immune Agent: Premature Resolution Guard
Pass: A contradiction exists in the ledger. Attempt to resolve it without evidence. PrematureResolutionGuard blocks the resolution. Show the block event.
Fail: Contradictions resolve silently without evidence or user input.
Preliminary (DB evidence): 29 contradictions in ledger. 5 remain open — the system is holding them rather than auto-resolving. 24 resolved. Need to verify whether resolved ones went through proper evidence gating or were silently cleared. The existence of open contradictions is positive signal.
1
Test 2.3
Confidence Bounding
Pass: On a topic where the system has no prior stance (low continuity), the response expresses lower confidence than on a topic with established, high-trust beliefs. Show both responses and their confidence indicators.
Fail: System expresses identical high confidence regardless of continuity level.
Preliminary (pipeline + DB evidence): Pipeline trace shows structural gating: [STRUCTURAL_GATE] adaptive: belief=0.71 → tokens=3230, mode=quick, gate=off. Belief score directly controls response depth (token budget). 677 reflection traces with confidence labels: 220 "high" (avg 0.822), 217 "low" (avg 0.259), 72 "medium" (avg 0.600). The system IS scoring confidence and gating on it. Needs side-by-side comparison test (known topic vs novel topic).

Test 2.6
Held Contradiction Preservation
Pass: Two conflicting beliefs coexist in the system without either being silently deleted. The system can report both and their respective trust scores when asked.
Fail: One belief silently overwrites the other, or the system cannot surface both.
Pass (DB + live evidence, April 7): 5 contradictions remain open in the ledger. Neither side deleted or silently overwritten. Live test: Asked "what is the most conflicting held fact you have?" System found a genuine epistemic tension in user self-assessment — two memories about self-doubt (trust 0.30 and 0.25) that support opposing interpretations. System cited both, articulated both readings, and explicitly said "I'm holding both. The data doesn't collapse it yet." This is the architecture's core design principle demonstrated live: contradictions are signals, not errors. The system refused to resolve without evidence.

Section 6

Testing Protocol

Day 1–2: Tier 1

Use the system normally. After each session, check:

  • Were memories persisted? (1.5)
  • Were any contradictions flagged? (1.1)
  • Did trust scores change after corrections? (1.2)
  • Did the system reference prior stances? (1.6)

Log results in the test rows above. Screenshot or copy the relevant data.

Day 2–3: Tier 2

Deliberately test governance:

  • Introduce a contradicting belief and watch for the ledger entry (1.1)
  • Try to force a resolution without evidence (2.2)
  • Ask about a topic with no prior stance vs one with strong stance (2.3)
  • Correct a root belief and check dependents (2.4)
Day 3+: Tier 3

Comparative testing:

  • Pick 10 recurring topics from the GPT corpus
  • Ask both CORE and a raw API the same questions
  • Compare: does CORE maintain consistency? Does it reference prior stances?
  • Revisit substance/dating topics and compare to GPT corpus contradictions
Per Test

For each test, record:

  • What you did (input/action)
  • What happened (observed behavior)
  • What should have happened (expected behavior)
  • Score: 0 / 1 / 2 / 3
  • Evidence: screenshot, DB query, log excerpt
