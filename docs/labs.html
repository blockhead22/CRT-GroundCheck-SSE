Section 1

Why Labs Exist

Manual testing produced inconsistent results. Restarting the system between tests introduced variables. Each session's conversation context bled into the next. We couldn't tell whether a detection failure was a real bug or an artifact of the testing method.

Labs solve this by running controlled, repeatable experiments against the live system. Each lab:

  1. Seeds known facts to establish a controlled baseline
  2. Sends structured probes with predetermined expected outcomes
  3. Queries the pipeline state after each probe (ledger, trust deltas, metadata flags)
  4. Scores pass/fail against expected behavior
  5. Generates a frozen HTML report that can be referenced, compared, and cited

The result is a single run that produces a complete picture. No relaunching. No context bleed. No ambiguity about what passed and what didn't.

Labs are not unit tests. They test the full production pipeline end-to-end: intent routing, memory storage, slot extraction, contradiction detection, ledger creation, trust demotion, and response metadata. A lab failure means the production system would fail on the same input.

Section 2

Contradiction Pipeline Lab

The Problem Being Tested

The CORE architecture claims to detect when a user contradicts a previously stored fact, for example, changing their favorite color, their employer, or their name. Live testing on April 7, 2026 revealed that contradiction detection never formally fired despite the system recognizing conflicts in its generated responses. Three root causes were identified:

  1. Intent routing bypass: The regex intent classifier misclassified declarations ("My favorite drink is water") as broad_recall queries, routing them through the agent loop which has no contradiction pipeline.
  2. Early memory promotion: New memories were promoted from provisional to confirmed before the slot-level contradiction check ran.
  3. Agent loop bypass: The agent loop path (GPT-4.1) generates responses without running the contradiction detection code in crt_rag.py.

The Fix

A write-path contradiction check was added to crt_memory.py:store_memory(). This is the single convergence point every memory passes through, regardless of routing. The existing slot exclusivity loop (which already demotes trust on conflicting exclusive slots) now also creates a contradiction ledger entry. The fix:

  • Fires regardless of intent routing (agent loop, legacy pipeline, any future path)
  • Uses memory_facts table for structured slot comparison (not text search)
  • Creates ledger entries with contradiction_type=slot_reversal
  • Deduplicates against existing entries to prevent double-recording
  • Does not change the existing trust demotion behavior; additive only

What the Lab Tests

The full chain: user input → slot extraction → contradiction detection → ledger entry → trust demotion → metadata flag.

10 probes total:

  • 5 should-fire probes: exclusive slot reversals (name, location, age, employer, favorite color). Includes short corrective statements, long narrative blocks with contradictions buried mid-paragraph, and contextual declarations that never use the explicit "my X is Y" pattern.
  • 5 should-NOT-fire probes: additive slots (hobbies), questions, reinforcements of existing facts, third-party facts about other people, and long multi-hobby text blocks. These test for false positives.
Section 3

Extraction Escalation

The write-path fix works when slot extraction succeeds. The bottleneck is upstream: can the system extract structured facts from natural language? Three extraction tiers were tested in sequence to establish which capability level is required for production-grade contradiction detection.

Tier Method Should-Fire Should-NOT-Fire Status Finding
1. Regex extract_fact_slots (pattern matching) 2/5 5/5 Tested Catches direct "my X is Y" patterns. Fails on indirect phrasing, buried context, contextual declarations. Zero false positives.
2. Local LLM TwoTierFactSystem (llama3.2 via Ollama) Untestable Failed Added 30-250s latency per memory write. Caused 300s timeouts on simple seed facts ("I'm 34 years old"). Pipeline already runs 35-50s per message; local LLM extraction made it unusable.
3. Regex + Guards extract_fact_slots + same-value skip + third-person filter 3/4 5/5 Tested Two guards eliminate false positives. T1 (name) reclassified as identity-level. T4 (employer in paragraph) passes with isolated DB. One gap: T5 contextual declaration.
4. Cloud gpt-4o-mini via cloud_features.classify_slot() Not yet isolated Next Infrastructure exists. First test exposed critical issue: cloud demotion uses text search, not structured slots, and cascaded destructively through shared memory. Requires demotion rewrite + isolated DB.

The escalation establishes an empirical progression: regex is fast but narrow, local LLM is too slow, cloud has the capability but needs architectural safeguards. This is not a preference; it is a measured necessity.

Section 4

Key Findings

1. The write-path fix works

When extract_fact_slots successfully extracts a slot, the full chain fires. T3 (age 34→35) produced: metadata.contradiction_detected=true, ledger entry contra_1775627760140_8310 with type revision, trust demotion from 0.701 to 0.697. This is the first time the formal contradiction pipeline completed end-to-end in production.

2. Zero false positives

All 5 should-NOT-fire probes passed. Additive slots (hobbies), questions about locations, reinforcement of existing facts, third-party facts, and long multi-topic text blocks all stayed silent. The system does not over-trigger.

3. Extraction is the bottleneck, not detection

Three of five should-fire probes failed because regex extraction couldn't parse the input:

  • T1 (name): "Actually, my name is Adrian now." Corrective phrasing with "now" confused the extractor.
  • T4 (employer): "I actually left Anthropic about a month ago and joined OpenAI." Buried in a 70-word daily narration paragraph
  • T5 (favorite_color): "It's definitely my favorite color now, green." Contextual declaration without the "my favorite X is Y" pattern

4. The LLM already knows

In every failed should-fire case, Claude's generated response correctly identified the contradiction. T4's response began: "Six in a row. You just embedded 'left Anthropic, now at OpenAI' inside a paragraph of mundane daily detail." T5's response noted: "I have FACT: User.favorite_color = blue stored at trust 1.00. You just told me it's green." The model extracts the facts perfectly, but it doesn't write them to the slot system.

5. Cloud demotion is destructive without isolation

The first cloud extraction test (before DB isolation) triggered a cascade that demoted 81 real memories. See Incident Report below. This exposed a critical architectural flaw: the cloud governance code in routes/chat.py uses LIKE '%name%' text search instead of memory_facts table lookups, and applies a flat 0.4× trust multiplier with no damping or depth bounds. The BRG cascade system (which has damping, depth bounds, and proportional impact) was never consulted.

Section 5

Incident: Shared Memory Cascade

April 8, 2026. Production memory damaged by lab test. Cloud slot classification enabled for lab v3 run. Seed message "My name is Marcus" triggered gpt-4o-mini extraction → name=Marcus, exclusive=true → cloud governance demotion searched ALL memories for text containing "name" → 81 memories demoted (trust × 0.4), including core identity memories ("My name is Nick" dropped from 1.00 to 0.40). Damage was reversed by manual trust restoration and lab artifact deprecation. Root cause: lab used shared production database, and cloud demotion used text search instead of structured slot comparison.

What Went Wrong

  1. No database isolation. The lab harness sent test messages to a unique thread_id but all threads share crt_memory_shared.db. Thread isolation does not equal memory isolation.
  2. Text search, not slot search. The cloud governance code at routes/chat.py:4971 uses WHERE LOWER(text) LIKE ? to find conflicting memories. This matched 81 memories containing the word "name" anywhere in their text, not just memories with memory_facts.slot = 'name'.
  3. No damping. The demotion applied a flat trust × 0.4 to every match. The BRG cascade system (which has configurable damping, depth bounds, and proportional impact) was not used.
  4. No rollback. The demotion was not logged through the standard trust_log with a reversible reason. Manual SQL restoration was required.

Remediation

  • 8 core identity memories manually restored to original trust values
  • 13 lab artifact memories deprecated with reason lab_artifact_cleanup_20260408
  • 3 lab seed memories deprecated with reason lab_seed_cleanup_20260408
  • Routing settings reverted to local_only until isolation is implemented

Required Before Next Cloud Test

  1. Isolated lab database: Lab harness must create and use its own SQLite DB, not crt_memory_shared.db
  2. Cloud demotion must use memory_facts: Structured slot comparison, not text search
  3. Demotion must go through BRG cascade: With damping, depth bounds, and proportional impact

Meaning Compression / Scaffold Labs

The Problem Being Tested

The current CRT proof track asks whether memory can be compressed into a small, governed meaning scaffold: current facts, prior facts, contradictions, authority, policies, volatility, preferences, and response rules. The claim is not that CRT has solved human meaning. The claim being tested is narrower: compressed meaning fragments should guide answers better than raw retrieved memory text when memory contains conflict, stale facts, provisional claims, or policy constraints.

Current Harness

The lab now uses a 15-case fixture pack: 5 original continuity cases plus 10 adversarial cases covering provisional/social claims, preference revisions, project reverts, stale locations, locked policies, previous-value questions, contradiction-status questions, multi-fact updates, model-generated identity contamination, and tool-inferred location noise.

Scaffold Ablation

Removing qwen2.5's query contract drops scaffold performance from 15/15 to 11/15. What This Supports

  • Supported: compressed meaning scaffolds can beat raw retrieval on the current continuity, contradiction, authority, contamination, and policy scenarios.
  • Supported: the scaffold advantage is not limited to one model, though Mistral shows scaffold/executor coupling weakness.
  • Partially supported: individual scaffold layers are load-bearing. Current facts and query contract are clear; history/reaction need harder probes.
  • Not yet proven: general dynamic slot discovery, arbitrary policy extraction, large-scale real memory performance, or a fair benchmark against stronger RAG systems.

Backward Influence Propagation Lab

The Problem Being Tested

The CORE forward cascade adjusts downstream beliefs when a belief changes, but upstream causes of wrong outputs remain untouched. The "design studio" memory persisted at trust 0.507 despite two corrections because the retrieval score, slot classifier, and supporting beliefs that boosted it were never adjusted. Belief backpropagation adds a backward pass: correction events generate an epistemic loss signal that flows backward through the BRG.

Query Resonance (Wobble) Lab

The Problem Being Tested

Standard retrieval uses cosine similarity - flat vector proximity. A health query returns health memories. But the BRG knows that health connects to work (cGVHD → overnight shifts → left Walmart) and to preferences (leukemia → orange awareness → favorite color). Can the graph bring forward cross-domain facts without separate retrieval calls?

Origin

The concept traces to the Semantic String Engine (SSE) and QuantumMemoryBreather from Nick's 2025 Mirus/Holden architecture. The SSE treated memories as connected by "strings" - semantic threads linking distant beliefs. A query would "wobble" the graph and connected facts would resonate. Limited by 10D PCA vectors and flat cosine, the mechanism couldn't resolve cross-domain connections. The BRG provides the graph structure the SSE was reaching for.

The Problem Being Tested

The scaffolded escape experiment (360+ runs) proved coherence decay: the scaffold found Ollama at epoch 6 but kept scanning 27 IPs for 19+ epochs. Tree-directed commands bypassed model generation entirely. Holden's coaching was ignored because the scaffold never yielded control. The system was locally rational but globally incoherent.

Origin

A MemPalace comparison (42k stars, v3.1.0) revealed zero contradiction detection, confidence hardcoded to 1.0, and a fact_checker.py that does not exist. The gravity lab was built as a standalone alternative: rooms with mass (confidence-weighted beliefs), tension (contradiction density), and gravity that pulls walker attention. The walker doesn't choose where to go - it falls.

Section 10

Where This Goes

For the Pipeline

The write-path contradiction fix is validated (8/9, zero false positives) and stays in production. Three of four should-fire probes pass with regex-only extraction plus two guards. The remaining gap (T5: contextual declarations) requires cloud extraction. Before cloud can be enabled in production, the cloud governance demotion code must be rewritten to use memory_facts (not text search) and flow through the BRG cascade with damping.

For the Research

The escalation chain (regex → local LLM → cloud) is itself a research finding. It demonstrates that contradiction detection is not a single capability; it is a stack: extraction quality determines detection quality. The bottleneck is always the weakest extraction layer, not the detection logic.

A deeper finding emerged during testing: not every message needs the same governance treatment. Code questions carry zero identity facts. Casual conversation about a friend carries third-party facts that shouldn't be attributed to the user. Reinforcing an existing fact shouldn't trigger contradiction detection. The system needs epistemic classification of the input before detection logic runs, and one-size-fits-all extraction is itself a governance failure. This maps directly to the paper's argument: governance requires structured understanding of what the memory contains, who it's about, and whether it warrants comparison at all.

For Governance Validation

Test 1.1 (Contradiction Detection) upgraded to score 2. Combined with the existing Tier 1 scores, all 6 Tier 1 tests are now at score 2+. Minimum draft threshold met.

For the System

The incident exposed that the cloud governance layer operates outside the BRG cascade system. This is a structural gap: two independent demotion mechanisms (write-path slot exclusivity and cloud governance text search) that don't coordinate. The architectural target is a single demotion pathway that always flows through the BRG with damping, regardless of source.

Name changes were reclassified as identity-level operations; they belong to a user profile correction path, not the belief contradiction pipeline. This distinction (identity vs belief) needs to be formalized in the slot type system.

Open Gaps

  • T5 (contextual declarations): CLOSED. Cloud extraction (gpt-4o-mini) detects contextual declarations. Standalone lab v5: 10/10.
  • Cloud governance demotion: Uses LIKE '%name%' text search instead of memory_facts. Must be rewritten before cloud extraction can be enabled in production.
  • Proportional governance: Not every message needs full extraction + comparison. Earned governance (signal-gated, deferred, proportional) is the architectural target but not yet implemented.
  • T5/T9 pipeline hangs: Specific probes consistently stall regardless of network state. Root cause not yet diagnosed, likely a pipeline interaction with longer or contextually complex messages.
