Chapter 1

Every conversation resets. Except this one.

A user asks their AI assistant about cannabis dosing while navigating an antidepressant transition. The system helps them measure their bowl size, offers harm-reduction guidance, and builds context around their medical situation. 192 days later, the same user returns. The system tells them to quit entirely. It doesn't remember the previous conversation. It doesn't know about the medication. It gives the opposite advice with the same confidence.

Neither session knew about the other.

If a system can't remember what it told you yesterday, it shouldn't be giving you advice today.

This is not a hypothetical. It's a real case from 59,370 messages across 13 months of conversation data, analyzed in the contradiction density paper. The contradictions concentrate in exactly the domains where inconsistency carries real consequences: health, identity, career, ongoing projects.

Every major AI assistant deployed today has this structural flaw. Each conversation starts from zero. Each response is generated with full confidence and no continuity. RAG adds retrieval, but retrieval is not belief. Finding a relevant document is not the same as knowing what you think about it, how confident you are, or whether it conflicts with something you said six months ago.

Time is the primary amplifier. The hard contradiction rate nearly doubles from 7% at short time gaps to 12.4% at 3+ months. The longer a user relies on the system, the worse it gets. And 93% of stance flips span 3+ turns, meaning no pairwise comparison catches them. A stricter v2 reanalysis confirmed the signal: of 40,200 candidate pairs, 98.9% were topic-boundary noise, but the 47 genuine contradictions that survived had the highest risk scores of any category.

For any system providing ongoing personal support, statelessness is a structural failure. The user builds trust over time. The system resets that trust every session while maintaining the appearance of continuity.

Chapter 2

The Thesis

The project started under a different name. CRT — Contradiction Reflective Transformer — was the original working title. The irony is that it never was a transformer. It was a governance layer built around a transformer. But the name stuck for over a year because it captured the intent: a system that reflects on its own contradictions instead of hiding them.

As the architecture matured, the name evolved to match what it had actually become. CORE — Contradiction, Observation, Revision, Epistemics — describes the four operations that run continuously beneath every conversation. The system observes what's said, checks it against what it believes, revises when evidence warrants, and treats the entire process as an epistemic problem: not "what's the right answer" but "what do I believe, how strongly, and does it conflict with something I believed before?"

CORE starts from three design laws. Not suggestions or best practices. Structural commitments that shape every decision in the architecture.

Law 1
Belief/Speech Separation
What the system believes and what it says are different things. The gap between them must be auditable. The LLM generates speech. The governance layer holds belief. When they diverge, the system flags it. It does not silently let the mouth overwrite the mind.
Law 2
Earned Contradiction Resolution
Contradictions are signals, not errors. They are preserved until evidence resolves them. Never silently overwritten. Full resolution must be earned through corroboration, trust hierarchy, or later confirmation.
Law 3
Emergent Structure Over Hardcoded Logic
Behavior emerges from memory, reflection, compression, and contradiction handling. Not from runtime hacks. The system tracks its own patterns. Regex is acceptable as a fast tier, but never the ceiling.

These three laws produce a single architectural insight that anchors the entire project:

Core Thesis
The model is the mouth. Persistence is the self.
Switching models in an agentic system is dangerous because most systems let the mouth become the self at every step. Every handoff is a tiny identity wipe. CORE externalizes the self into a persistent governance layer that survives model switches, session boundaries, and provider changes.

Three things must persist across every boundary: task state (what are we doing), uncertainty state (what do we know and how well), and governance state (what rules apply, what is held, what is forbidden). If any of these reset, the system drifts even when every individual model works as designed.

Chapter 3

How It Got Built

The governance framework was not designed. It was discovered. Each mechanism started as a specific fix for a specific failure. The failures accumulated into an architecture.

The first version tried to reconstruct responses from compressed memory. A small transformer trained on real conversations. It would compress a thought, rebuild it, and check if the meaning survived the round-trip. Most of the time it didn't. So a check was built: after generation, compare the output to the memory it came from. If similarity dropped below threshold, flag it, retry, or refuse to answer. Compress, inflate, collapse, validate. That became the fidelity mirror. The first governance mechanism, disguised as debugging.

Then the system started storing bad outputs as memories. A fallback model would hallucinate something, and the memory layer would index it alongside real facts. Next session, the hallucination would get retrieved and repeated with confidence. So quarantine was built: low-confidence outputs get marked, stored separately, skipped during retrieval. That became trust-tiered memory storage.

Then contradictions piled up. The system said one thing Tuesday and the opposite Thursday and never noticed. A contradiction manager was built. Not to resolve contradictions, but to hold them. To say: these two beliefs conflict, and I'm not going to pretend they don't. That became the held contradiction design law.

Then corrections didn't fix what caused them. The correction was absorbed at the leaf. The root cause survived. So a backward pass was built: when a correction happens, the error signal flows upstream through the dependency graph, adjusting trust on every belief that contributed to the wrong output. That became belief backpropagation. Validated 30/30. No direct precedent found.

I didn't design governance. I discovered it. Each fix was a scar from a failure. The scars accumulated into an architecture.

The pattern behind every fix was the same thing from different angles: measuring the distance between what the system said and what the evidence supported, and enforcing that distance. At generation time. At storage time. At retrieval time. Across the entire graph.

Today the system runs a 12-step pipeline with 6 governance layers and 5 autonomous immune agents that enforce constitutional laws in real time. The agents are structural, not advisory. The system cannot violate its own principles even if the LLM wants to.

Chapter 4

The Research

None of this started as research. Every paper exists because building the system exposed a question that demanded formal investigation. The math followed the engineering, not the other way around.

What happens when you change one belief?

In a system with hundreds of interconnected memories, a single correction can propagate. We formalized the Belief Dependency Graph and proved depth bounds, damping conditions, and instability thresholds. The unexpected finding: held contradictions act as natural firewalls. Not all contradictions should be resolved. Some of them are load-bearing.

Cascade Complexity →

What happens when the output was wrong?

Forward cascades adjust downstream beliefs, but the upstream causes remain untouched. Belief backpropagation sends error signals backward through the dependency graph, adjusting trust on every belief that contributed to the wrong output. Wrong beliefs self-prune. Domain volatility becomes measurable. The system's beliefs about itself participate in the same dynamics. 30/30 validation. No direct precedent found.

Belief Backpropagation →

Do different models fail differently?

Yes. Three fundamentally different failure modes across three model families under identical conditions. Qwen3 fractures hard on specific factuals. Mistral drifts on morals but locks on facts. DeepSeek fogs uniformly. A governance layer that assumes uniform model behavior will fail.

Variance Probing →

Does belief structure survive compression?

3-bit quantization preserves the full epistemic structure: identical gradients, 92.9% anchor basin stability. 2-bit breaks it: basins merge, edges drift, anchor assignments flip. The metric for compression success is not cosine similarity. It's whether the gravitational centers that organize 77% of memories maintain their topology.

Chapter 5

What's Running

Aether is not a prototype. It's a production system in daily use, governing real conversations through the full CORE pipeline. 820+ persistent memories. 135+ features shipped. Every message passes through 12 pipeline stages with governance checkpoints woven throughout.

The system routes across local models and cloud providers, with automatic fallback chains and model-aware fragility governance. When alignment drops below threshold, the system forces memory re-retrieval. After 3 consecutive drifts, it halts and asks the user. When corrections resolve contradictions, error signals flow backward through the belief graph, adjusting every upstream belief that contributed to the wrong output.

The eval harness scores production data continuously. Retrieval accuracy: 0.559. Trust calibration: 0.694. Governance compliance: 0.900. These are honest numbers from real conversations, not cherry-picked benchmarks. The system publishes its own weaknesses.

Chapter 6

Where It Goes

CORE is being extracted into aeteros-core, an open-source framework that any AI system can use as its epistemic governance layer. The persistent belief state, contradiction tracking, immune agents, and governance pipeline are not Aether-specific. They are general-purpose infrastructure.

The business path is governance-as-a-service: CORE as middleware that sits between any application and any LLM provider. You keep your existing stack. CORE adds the belief layer, the contradiction detection, the drift governance, and the immune system. An OpenAI-compatible proxy that adds epistemic integrity without requiring you to rewrite anything.

The timing is not accidental. The EU AI Act (Article 50, effective August 2026) requires transparency infrastructure for AI systems that interact with humans. CORE provides exactly this: auditable belief states, logged contradictions, measurable belief/speech gaps, and governance compliance scores.

When interpretability APIs mature and providers expose the emotion vectors and activation patterns that Anthropic has already identified internally, CORE is ready to integrate directly. The governance layer is built. It is waiting for the sensors.

The latest research direction — belief backpropagation — adds structural learning to the governance layer. The system doesn't just detect errors; it propagates error signals backward through the belief graph and adjusts every upstream belief that contributed to the wrong output. Four publishable theorem targets have been identified, including a connection to active inference (Friston's free energy framework) that would give CORE formal grounding in computational neuroscience.

The Trajectory
Agentic systems that persist across sessions need a belief state.
The question is whether they build it with governance or without. CORE is a case for governance-first: the math works, the architecture scales, the production system runs, and the regulatory environment is arriving.
