Section 1

Core Concepts

CORE CORE-Original
Contradiction, Observation, Revision, Epistemics. Originally CRT (Cognitive-Reflective Transformer).
A memory governance framework for AI systems built on three design laws: belief/speech separation, earned contradiction resolution, and emergent structure over hardcoded logic. CORE treats memory as the source of identity and LLM generation as downstream expression. Every response is grounded in trust-scored memories rather than raw model output.
Example
A user says "I moved to Austin." CORE doesn't just store the text. It revises the trust on "lives in Portland," triggers a cascade to dependent memories (commute, weather preferences, local restaurants), and marks the old location as superseded rather than deleted.
Related: Belief, Speech, Trust, Cascade
Belief CORE-Original
CORE-specific meaning, distinct from standard epistemology. Opposite of Speech.
A memory-grounded response backed by trust evidence from the memory store. When CORE classifies a response as "belief," it means the system found supporting memories with sufficient trust scores. Belief is the system's earned knowledge: what it can justify, not just what it can generate.
Example
User asks "What's my dog's name?" The system retrieves a memory "User's dog is named Mochi" with trust 0.92. The response is classified as belief (mode C) because it is backed by high-trust evidence.
Related: Speech, Belief/Speech Separation, Trust, SSE Mode
Speech CORE-Original
CORE-specific meaning. The opposite of Belief.
A model-generated response without memory support. Speech comes from the LLM's weights (its training data, not the system's lived experience). Speech is useful (the model knows things the memory store doesn't), but it cannot upgrade itself to belief status. The system must mark speech as provisional and never let it silently overwrite trusted memories.
Example
User asks "What's the capital of France?" No memory exists for this. The LLM generates "Paris" from its weights. The response is classified as speech (mode S), correct but not memory-backed.
Related: Belief, Belief/Speech Separation, Law 1
Belief/Speech Separation Design Law 1
CORE Design Law 1. "The mouth should never outweigh the self."
The gap between internal state (belief) and expressed output (speech) must be auditable at all times. LLM generation is a downstream act, vocal cords rather than an epistemic authority. If a fallback model contradicts memory, the conflict is logged and the response is marked degraded, never silently adopted. The system may hold unresolved tension internally without collapsing it into a false confident answer.
The gap is measured as: gap = |belief_score - speech_score| where belief_score comes from memory retrieval trust and speech_score comes from LLM confidence. Enforced by GapAuditor.
Example
The LLM generates "You work at Google" but memory says "User works at Microsoft" (trust 0.88). Belief/speech separation ensures the memory wins. The gap is logged. The LLM's claim is discarded.
Related: Belief, Speech, Gap, Law 5
Trust CORE-Original
CORE-original. Distinguished from Confidence.
A 0-1 score on a memory that evolves over time through evidence. Trust is earned, not assigned. It increases when corroborating evidence arrives, decreases when contradicting evidence appears, and decays under drift. Trust governs whether a memory can influence responses, survive compaction, or participate in cascade propagation. The key distinction: trust changes; confidence is static.
Trust evolution follows CRTMath: \(\text{trust}_{t+1} = \text{trust}_t + \eta \cdot (\text{evidence} - \text{trust}_t)\) where \(\eta\) is the adjustment rate, a scaling factor modulated by source authority and corroboration count (not an optimized parameter).
Example
A memory "User likes hiking" starts at trust 0.5. The user mentions hiking three more times over a week. Each mention bumps trust via CRTMath. After a month, trust reaches 0.87. Now it's a high-confidence belief that survives compaction.
Related: Confidence, Authority, Governance Bridge
Confidence Standard
Standard term, redefined in CORE to contrast with Trust.
The initial certainty assigned to a memory at storage time, typically based on how explicitly the user stated it. Confidence is a snapshot; it captures the moment of observation but never updates afterward. A user saying "I live in Austin" gets high confidence (explicit statement). The system inferring location from context gets low confidence. Trust starts near confidence but diverges as evidence accumulates.
Example
"I'm allergic to peanuts" is stored at confidence 0.95 (direct, explicit). "Seems like you prefer morning meetings" is stored at confidence 0.4 (inferred). Both start with trust near their confidence, but trust evolves independently from there.
Related: Trust, Belief Locus
Memory CORE-Original
CORE-specific meaning. More than a stored string.
A stored fact, observation, or preference with trust score, embedding vector, authority level, timestamps, and metadata. Memories are the atoms of the belief system, each one a node in the BRG and a Belief Locus in semantic space. Memories have kinds (observation, preference, fact, correction) and authority levels (locked, confirmed, provisional). They are never silently deleted; only deprecated, superseded, or compacted.
Example
{ text: "Nick works at home on Fridays", trust: 0.78, kind: "observation", authority: "confirmed", embedding: [0.12, -0.04, ...], created: "2026-03-15" }
Related: Trust, Belief Locus, BRG, Authority
Section 2

Belief Geometry

Belief Locus CORE-Adapted
Inspired by 3D Gaussian Splatting (Kerbl et al., 2023), adapted for epistemology. Formerly called "Gaussian Splat" in early CORE docs.
A memory modeled as a probability distribution in semantic space rather than a single point. Each locus has a center (where the belief lives), a covariance (the shape and extent of its uncertainty), a confidence (how much it contributes to the world model), and a timestamp. A tight locus represents a settled belief; a wide locus represents an uncertain or contested one. The covariance encodes where the uncertainty lives, not just how much.
\[\mathcal{L} = (\mu, \Sigma, \alpha, t)\] where \(\mu \in \mathbb{R}^d\) is the center embedding, \(\Sigma \in \mathbb{R}^{d \times d}_{++}\) is a positive-definite covariance matrix (diagonal in Phase 1: \(\Sigma = \mathrm{diag}(\sigma_1, \ldots, \sigma_d)\)), \(\alpha \in [0,1]\) is confidence, and \(t\) is the last-modified timestamp.
Example
"Nick likes hiking" is stored as a locus with tight covariance (high certainty, many corroborations). "Nick might be interested in woodworking" is a locus with wide covariance (mentioned once, uncertain). Both live in the same 384-dimensional semantic space, but the hiking locus is a sharp peak while the woodworking locus is a broad blob.
Related: Locus Overlap, Locus Contraction, Semantic Space, Memory
Locus Overlap CORE-Original
Uses Bhattacharyya coefficient from statistical distance theory, applied to belief geometry.
A geometric measure of contradiction between two belief loci. Two loci with high spatial overlap but opposing semantic content represent tension: the system holds conflicting beliefs in the same region of meaning-space. Overlap is continuous (0 to 1), replacing the binary "contradicts / doesn't contradict" classification with a graded signal.
Bhattacharyya coefficient for diagonal loci: \[\text{BC}(\mathcal{L}_1, \mathcal{L}_2) = \prod_{i=1}^{d} \left(\frac{2\sqrt{\sigma_{1i}\sigma_{2i}}}{\sigma_{1i} + \sigma_{2i}}\right)^{1/2} \exp\!\left(-\frac{(\mu_{1i}-\mu_{2i})^2}{4(\sigma_{1i}+\sigma_{2i})}\right)\]
Example
"I love my job" and "My job is killing me" have embeddings close in the "job" region of semantic space. Their loci overlap significantly. NLI confirms semantic tension. The overlap integral quantifies exactly how much contradiction exists. A value of 0.73 means substantial conflict, not just binary "they contradict."
Related: Belief Locus, Contradiction, Held Contradiction
Locus Contraction CORE-Original
CORE-original. Geometric interpretation of trust increase.
When new evidence supports a belief, its locus contracts: the covariance tightens, representing increased certainty. Each corroboration narrows the distribution, and the system becomes more precise about what it believes. Contraction is the geometric manifestation of trust growth.
Update rule: \(\sigma_i' = \sigma_i \cdot (1 - \eta \cdot \text{evidence\_strength})\) where \(\eta\) is the contraction rate. Bounded below by \(\sigma_{\min} = 10^{-8}\) to prevent degenerate distributions.
Example
User mentions hiking five times across different conversations. Each mention triggers contraction on the "likes hiking" locus. After five corroborations, the covariance is 40% tighter than at creation. The system is now very certain about this preference.
Related: Belief Locus, Locus Expansion, Trust
Locus Expansion CORE-Original
CORE-original. Geometric interpretation of trust decrease or challenge.
When contradicting evidence arrives or trust decays, the locus expands: the covariance widens, representing increased uncertainty. The system is less sure about what it believes. Expansion is the geometric manifestation of challenge. The belief hasn't been destroyed, but the system now holds it more loosely.
Example
The system believed "Nick prefers mornings" (tight locus). Then Nick schedules three evening meetings. The locus expands; the system isn't sure anymore. It hasn't deleted the morning preference, just widened its uncertainty about it.
Related: Belief Locus, Locus Contraction, Contradiction
Semantic Space Standard
Standard NLP concept. CORE uses all-MiniLM-L6-v2 (384 dimensions).
The embedding vector space where all memories live as belief loci. Every text memory is embedded into a 384-dimensional space where cosine similarity approximates semantic similarity. Related memories cluster together; unrelated memories are distant. This space is the stage on which all geometric operations (overlap, contraction, expansion, Fisher-Rao distance) play out.
Example
"Likes hiking" and "enjoys mountain trails" are close in semantic space (cosine similarity ~0.85). "Likes hiking" and "prefers sushi for dinner" are far apart (~0.12). The BRG's SUPPORTS and CONTRADICTS edges are partly derived from distances in this space.
Related: Belief Locus, BRG, Locus Overlap
Section 3

Contradiction & Cascade

Contradiction Adapted
Adapted from NLI (Natural Language Inference) and Belnap four-valued logic. CORE adds disposition classification.
Two memories that conflict, detected via NLI scoring and semantic similarity. CORE's key innovation: contradictions are not all the same. Each is classified into one of three dispositions: RESOLVABLE (one side is wrong or outdated), HELD (both sides carry evidence and must be preserved), or EVOLVING (the user is changing their mind and neither side has won). A fourth category, CONTEXTUAL, captures beliefs that express differently depending on context rather than truly conflicting.
Example
"Meeting is Monday" vs "Meeting is Tuesday" → RESOLVABLE (one is wrong). "I love my job" vs "My job is killing me" → HELD (both are true). "I'm going vegan" (last month) vs "I ordered steak" (yesterday) → EVOLVING (still in flux).
Related: Held Contradiction, Contradiction Ledger, Belnap State, Locus Overlap
Held Contradiction CORE-Adapted / Design Law 2
CORE-original. Based on Belnap's four-valued logic (TRUE, FALSE, BOTH, NEITHER). No prior AI memory system implements disposition-classified contradictions.
A contradiction deliberately preserved because both sides carry legitimate evidence. This is not an error; it is a signal. Held contradictions reflect the reality that humans live in genuine tension: "I'm an introvert" and "I love performing on stage" are both true simultaneously. Forcing resolution would produce a system that lies by oversimplifying. Held contradictions also serve as cascade firewalls, blocking belief revision from propagating through contested territory.
In Belnap terms, both memories are assigned the state \(\mathbf{B}\) (Both). The ledger records the pair with disposition HELD. Cascade propagation is blocked at held nodes (Proposition 5.3 in the cascade paper).
Example
"I'm disciplined" (true at work) and "I have no willpower" (true at home with snacks). Both carry trust above 0.6. The system holds both, returns whichever is contextually relevant, and never silently resolves the tension. The held contradiction IS the most accurate representation of the user.
Related: Contradiction, Firewall, Belnap State, Law 3
Contradiction Ledger CORE-Original
CORE-original. Immutable audit trail for all contradictions.
An append-only log of every contradiction detected, including both memory IDs, NLI scores, disposition classification, resolution method (if resolved), and timestamps. No contradiction is ever silently overwritten. The ledger answers questions like "what did the system disagree about?" and "how was this contradiction resolved?" It is the audit surface for Design Law 2.
Example
Ledger entry: { id: "c-4821", mem_a: "m-102", mem_b: "m-387", nli_score: 0.91, disposition: "HELD", resolved: false, detected_at: "2026-03-28T14:22:00Z" }
Related: Contradiction, Held Contradiction
BRG (Belief Relationship Graph) CORE-Adapted
CORE-original (Definition 3.2 in the cascade paper). Originally named as a dependency graph; evolved into a belief relationship graph as edge types grew beyond simple dependency. The acronym BRG is retained for consistency across the research papers.
A weighted directed graph where nodes are beliefs (memories with trust scores) and edges encode typed relationships: CONTRADICTS (semantic tension), SUPPORTS (evidential grounding), SUPERSEDES (temporal update), and RELATED_TO (topical similarity). The BRG is the structure through which cascades propagate, the backward influence flows, and the reflection loop walks. When used as a reasoning scaffold, the graph produces tree-like structures - branches are hypotheses, leaves are verifiable facts. The graph is the memory. The tree is the reasoning derived from it.
\[G = (V, E, w)\] where \(V = \{b_1, \ldots, b_n\}\) are belief states, \(E \subseteq V \times V\) are typed directed edges, and \(w: E \to (0, 1]\) encodes dependency strength.
Example
Memory "lives in Portland" has SUPPORTS edges to "commute is 20 minutes," "favorite coffee shop is Stumptown," and "weather preference is rain." Revising the location triggers cascade evaluation on all three dependents. The production BRG has 599 nodes and ~4,976 edges with average fan-out \(d \approx 8\).
Related: Cascade, Memory, Firewall
Cascade CORE-Adapted
CORE-original (Definition 3.5 in the cascade paper). Applies DeGroot-style dynamics to a single agent's internal belief state, a gap no prior framework addresses.
When one belief changes, the impact propagates through the BRG to dependent beliefs. Each affected node receives an impact scaled by edge weight and damped by a Lipschitz constant. Cascades are the mechanism by which a single new fact ("I moved to Austin") triggers broad belief revision across dozens of dependent memories. Propagation follows topological order on DAGs.
Impact at successor node \(v'\): \[\delta(v') = L_{v'} \cdot w(v, v') \cdot \delta(v)\] where \(L_{v'}\) is the local Lipschitz damping constant and \(w(v,v')\) is the dependency weight. Multi-parent aggregation uses max (not sum) to preserve geometric decay.
Example
User says "I moved to Austin." The cascade revises: commute time (impact 0.72), weather preferences (0.65), local restaurants (0.58), but does NOT touch "favorite team is the Lakers" (no dependency edge). Each hop attenuates the impact by the damping factor.
Related: BRG, Damping, Cascade Depth, Cascade Width, Cascade Pressure
Cascade Depth Theorem 4.1
Proven in the cascade paper. Bounded by longest DAG path.
The maximum number of hops from the initial revised node to the furthest affected node in a cascade. On a DAG, cascade depth is bounded by the longest directed path; the cascade cannot reach further than the graph structure allows. This is a structural bound, independent of edge weights or damping.
\[\text{depth}(C(r)) \leq \text{longest\_path}(G)\]
Example
If the longest chain in the BRG is location → commute → schedule → meeting habits (depth 3), then no cascade can affect nodes more than 3 hops from the source, regardless of how dramatic the initial revision was.
Related: Cascade, Cascade Width, BRG
Cascade Width Theorem 4.2
Proven in the cascade paper. Bounded by out-degree.
The maximum number of nodes affected at any single depth level of a cascade. Width grows exponentially with depth up to the graph size. A node with fan-out \(d\) can affect up to \(d\) nodes at the next level, each of which can affect \(d\) more, giving \(O(\min(d^k, n))\) at depth \(k\).
\[\text{width}(C(r), k) = O(\min(d^k, n))\] where \(d\) is maximum out-degree and \(n\) is total nodes.
Example
The production BRG has \(d \approx 8\). At depth 1, up to 8 nodes are affected. At depth 2, up to 64. At depth 3, up to 512, nearly the entire 599-node graph. This is why damping is essential.
Related: Cascade, Cascade Depth, Damping
Cascade Pressure CORE-Original
CORE-original (April 2026). Maps to "desperation precursor" in emotion governance theory.
The sum of all incoming impacts at a node from active cascades. Measures cumulative stress on a belief. High cascade pressure means the system is under duress: many of this belief's foundations are shifting simultaneously. Pressure is the quantitative trigger for governance intervention: when pressure exceeds a threshold, the system may escalate to the user or pause cascade propagation.
Example
A memory about "preferred work schedule" receives cascade impacts from three simultaneous revisions: location change (0.4), new job (0.6), and timezone shift (0.3). Total pressure = 1.3. This exceeds the intervention threshold, so the system asks the user to clarify rather than auto-revising.
Related: Cascade, Damping, Instability
Damping Theorem 4.3
Adapted from DeGroot consensus dynamics (1974), applied to single-agent belief revision. The single-agent analog of DeGroot's convergence theorem.
A geometric decay factor that prevents runaway cascades. The damping condition \(\rho = L \cdot w_{\max} < 1\) guarantees that per-node impact decays exponentially with depth. When damping holds, a cascade cannot amplify; each hop reduces the impact by at least factor \(\rho\). Graph-wide convergence requires the stricter condition \(d \cdot \rho < 1\) (Corollary 4.3.1).
Per-node bound: \(\delta(v) \leq \rho^{d(v)} \cdot \delta_0\) where \(\rho = L \cdot w_{\max}\), \(d(v)\) is depth of node \(v\), and \(\delta_0\) is initial impact.
Graph-wide total: \(\sum_{v \in S} \delta(v) \leq \frac{\delta_0}{1 - d \cdot \rho}\) when \(d \cdot \rho < 1\).
Example
With \(L = 0.9\) and \(w_{\max} = 0.95\), \(\rho = 0.855\). An initial impact of 1.0 becomes 0.855 at depth 1, 0.731 at depth 2, 0.625 at depth 3. The cascade fades. But with \(d = 8\), \(d \cdot \rho = 6.84 \gg 1\), so graph-wide reach is broad even though per-node impact decays.
Related: Cascade, Instability, Firewall
Instability Theorem 4.4
Proven in the cascade paper. Formalizes cognitive dissonance spirals.
When the BRG contains cycles with strong coupling (spectral radius \(\lambda > 1\)), cascade impact amplifies instead of decaying. Each traversal of the cycle strengthens the revision signal. This is the formal analog of a cognitive dissonance spiral: revising A forces revision of B, which forces revision of A again, each time stronger. The system must detect and break these cycles.
For a cycle \(C = (v_1, \ldots, v_k, v_1)\), let \(\lambda = \prod_{i} L_i \cdot w(v_i, v_{i+1})\). If \(\lambda > 1\), iterated cascade diverges: \(\delta^{(t)} \to \infty\).
Example
"I should exercise more" → "I feel guilty about not exercising" → "I'm stressed" → "I cope by skipping exercise" → "I should exercise more." If all edges are strong (\(\lambda > 1\)), each revision amplifies guilt, creating a runaway spiral. A held contradiction at any point breaks the cycle.
Related: Damping, Cascade, Firewall, Held Contradiction
Firewall Proposition 5.3
CORE-original (Proposition 5.3 in the cascade paper). Connects epistemic pluralism to system stability.
A held contradiction that blocks cascade propagation. Because a held contradiction's disposition is "do not resolve," no revision event can propagate through it. This makes held contradictions natural circuit-breakers in the BRG. They bound how far a cascade can reach, not by attenuating impact (like damping) but by completely stopping propagation at the contested boundary.
Example
A cascade from "I moved to Austin" would normally propagate to work preferences via a chain of dependencies. But a held contradiction sits between location and work style ("I love working in offices" vs. "I do my best work from home"). The cascade stops at the firewall. Work style beliefs are insulated from the location change.
Related: Held Contradiction, Cascade, Damping
Backward Influence Propagation CORE-Original
CORE-original (April 2026). Previously referred to as "belief backpropagation" and "reverse cascade" in early drafts. Renamed to avoid conflation with neural network backpropagation (gradient descent via chain rule). This mechanism is damped influence propagation on a weighted directed graph, not calculus-based gradient computation. No direct precedent identified in literature searches to date.
When a correction event resolves a contradiction, the resolution generates an epistemic loss signal that flows backward through the BRG's dependency edges, adjusting trust scores on every upstream belief that contributed to the incorrect output. The inverse of a forward cascade: cascades answer "if I change X, what else changes?" while backpropagation answers "the output was wrong - what beliefs caused it?" Three behaviors emerge naturally: self-pruning, domain volatility measurement, and reflexive self-model calibration. Validated with 30/30 lab checks; bidirectional convergence confirmed with contraction ratio 0.13.
Backward gradient per upstream node \(A\): \[\nabla(A) = L(B) \cdot w_{A \to B} \cdot \alpha^{d(A)}\] Trust adjustment: \(\tau'(A) = \tau(A) - \eta_{\text{domain}} \cdot \nabla(A)\), where \(\eta\) is the domain-specific volatility-driven adjustment rate (a scaling factor, not an optimized parameter).
Example
"Nick works at a design studio" is corrected twice. The backward pass traces upstream: the retrieval scoring that boosted this memory, the slot classifier that tagged it as "employer," and an old conversation node that mentioned design work. All three have their trust reduced. The memory doesn't just get demoted - the reasons it survived get demoted.
Related: Cascade, BRG, Epistemic Loss, Self-Pruning, Domain Volatility, Damping
Query Resonance (Wobble) CORE-Original
CORE-original (April 2026). Originated as the Semantic String Engine (2025). The forward complement to backward influence propagation. Informally called "wobble" - the formal name is query resonance.
When a query vector lands in the BRG, every node receives direct activation from cosine similarity. That activation then propagates through SUPPORTS edges, damped at each hop. Nodes that are far from the query in vector space but connected to resonant nodes through dependency edges also activate. The resonance pattern surfaces memories that cosine retrieval alone would miss - a health query brings forward work facts and preference facts because the BRG knows they are causally connected. Three resonance patterns emerge: tight (single-basin, confident), scattered (multi-domain, synthesize), and silent (unknown, refuse). Validated on 867 production memories; wobble survives 3-bit compression (7/8 top memories preserved).
Direct: \(r_0(v) = \cos(q, \mu_v)\). Propagated: \(r_{k+1}(v) = \max(r_k(v), \max_{u \to v} r_k(u) \cdot w_{uv} \cdot \alpha)\). Total: \(R(v) = r_0(v) + r_{\text{fwd}}(v) + r_{\text{back}}(v)\).
Example
Query: "How is your cGVHD?" Direct cosine finds cGVHD and leukemia memories. Wobble propagates through edges: cGVHD → overnight shifts hard → left Walmart → self-employed. Also: leukemia → orange awareness → favorite color. A health query returns work context and preference context because the graph knows they're connected.
Related: Cascade, BRG, Backward Influence Propagation, Semantic String
Semantic String CORE-Original
CORE-original. First conceptualized in the Mirus/Holden Semantic String Engine (SSE, 2025). Not "string" as in text - "string" as in the thread connecting two distant beliefs into shared meaning.
A cross-domain dependency edge in the BRG that connects beliefs from different semantic basins. "I like orange" connects to the health domain (leukemia awareness), the aesthetic domain (warm tones), the seasonal domain (October birthday), and the work domain (freelance creative identity). The strings radiating from a single node define its meaning - not the vector, but the topology. A belief with many cross-domain strings is a bridge node; removing it would disconnect multiple basins. The wobble mechanism discovers strings by measuring which distant nodes co-activate when a query lands.
Related: Query Resonance, BRG, Backward Influence Propagation
Epistemic Error Signal CORE-Original
CORE-original. The correction-weighted magnitude that drives the backward pass in belief backpropagation. Not a loss function in the ML optimization sense - it is not minimized during any training loop.
A scalar measuring the severity of a correction event. Higher when the system was very confident and wrong, when the same belief has been corrected multiple times, when a user (highest authority) corrected it, and when the error persisted for a long time. This scalar determines how much upstream beliefs need to adjust - it is a weighting factor for the backward pass, not an objective being optimized.
Related: Backward Influence Propagation, Trust, Contradiction
Self-Pruning CORE-Original
Consequent behavior of belief backpropagation. Not a separate mechanism - follows directly from cumulative trust adjustment and a deprecation threshold.
A belief that repeatedly appears on the wrong side of resolved contradictions accumulates negative adjustment from multiple backward passes. When its trust drops below the deprecation threshold, the memory is pruned - a consequence of cumulative error signals converging on the same node, not an explicit pruning rule. The key advantage over flat 0.4x demotion: the backward pass also erodes upstream trust, so the retrieval and classification systems that boosted the wrong memory also adjust.
Related: Backward Influence Propagation, Trust, Epistemic Loss
Domain Volatility CORE-Original
Consequent behavior of belief backpropagation. Domain-specific calibration independently validated by Le (2026) on prediction market data.
The recency-weighted ratio of corrections to assertions within a belief domain. High volatility means the domain has been frequently corrected; low volatility means it is stable. The system uses volatility to adapt its behavior per-domain: volatile domains get higher learning rates (corrections take effect faster), lower assertion confidence (the system hedges), and more retrieval verification. Measured, not configured - the system doesn't need a rule saying "be careful about employment." It measures that employment has been corrected 3 times in 48 hours.
Related: Backward Influence Propagation, Trust, Reflexive Self-Model
Reflexive Self-Model CORE-Original
Consequent behavior of belief backpropagation. No direct precedent identified for self-model beliefs participating in the same trust graph as world-beliefs.
The system's beliefs about itself - "I am reliable on employment facts," "my confidence tracks my accuracy" - are nodes in the BRG like any other belief, subject to the same backward pass and trust dynamics. When the system is repeatedly wrong about employment, the backward pass erodes "I am reliable on employment facts" while leaving "I am reliable on identity facts" untouched. This is personality as a consequence of epistemic history: the system becomes cautious where it has been wrong, not where a rule tells it to hedge.
Related: Backward Influence Propagation, Domain Volatility, Belief/Speech Gap
Section 4

Governance

Gate CORE-Original
CORE-original. Checkpoint pattern for response quality control.
A checkpoint in the pipeline that blocks or modifies a response based on evidence quality. Gates enforce governance rules before the response reaches the user. Types include: intent alignment gate (does the response match the query?), memory alignment gate (is the response supported by memory?), grounding gate (are claims verifiable?), and contradiction gate (does the response conflict with known beliefs?).
Example
The LLM generates a confident answer about the user's job. The memory alignment gate checks: does any memory support this claim? If trust is below 0.3, the gate downgrades the response from belief to speech and adds a hedge prefix.
Related: Structural Gate, 12-Step Pipeline, Belief/Speech Separation
Structural Gate CORE-Original
CORE-original (April 2026). Advisory governance replaced by structural governance; the gate constrains output shape, not just content.
Confidence-based response depth control. Instead of advising the LLM to "be less confident" (which it ignores), the structural gate constrains how many tokens the response can contain based on belief score. Low confidence → fewer tokens, hedge prefix. High confidence → full response. This is structural because it physically limits the output rather than hoping the model complies.
Adaptive depth formula: \(\text{tokens} = 100 + 3896 \times \text{belief}^{0.7}\)
Example
Query about a topic with belief score 0.2: structural gate limits response to ~370 tokens and prepends "Based on limited information..." Query with belief score 0.95: full 4000-token budget, no hedging.
Related: Gate, Adaptive Depth, Trust
Gap CORE-Original
CORE-original. The measurable distance between what the system knows and what it says.
The measured distance between belief-layer confidence (what memory supports) and speech-layer output (what the LLM generates). A gap of 0.0 means full transparency: the system said exactly what it believes. A gap of 1.0 means complete withholding. The GapAuditor (Law 5) enforces that this gap is always tracked and never silently grows. Gap trend detection catches the system becoming inadvertently deceptive.
Example
Memory says "Nick works at Microsoft" (trust 0.88). The LLM generates a response that mentions working at a tech company without specifics. Belief score = 0.88, speech specificity = 0.3. Gap = 0.58. The auditor flags this: why is the system hedging on something it's confident about?
Related: Belief/Speech Separation, Law 5
Governance Bridge CORE-Original
CORE-original. Connects two previously independent data stores: memories table and belief_speech tracking.
Bidirectional feedback between memory trust scores and belief/speech tracking. Three loops: (1) Drift → Trust Penalty: high topic instability penalizes supporting memories (drift threshold 0.4). (2) Trust Drop → Reclassification: when memory trust drops below 0.3, stale beliefs that depended on it are demoted from belief to speech. (3) Cross-validation at Recording: when storing new beliefs in unstable topics, trust is dampened by 0.85x.
Example
The system's responses about "favorite restaurant" keep flipping (high drift). Loop 1 detects this and penalizes the supporting memories. Loop 2 reclassifies the "favorite restaurant" belief to speech. Loop 3 ensures that the next restaurant mention is stored with dampened trust.
Related: Trust, Drift, Belief, Speech
Immune Agent CORE-Original
CORE-original (Mirus/Holden architecture). Six agents enforcing six constitutional laws.
An autonomous governance agent that watches the pipeline and enforces one of six constitutional laws. Immune agents operate independently, each monitoring a specific failure mode. They fire when a violation is detected and can block, modify, or flag a response. Named after the immune system analogy: the agents patrol for pathogens (governance violations) without needing central coordination.
Example
The TemplateDetector (Law 2) monitors response generation. It detects that the model produced the same hedge phrase "there are multiple perspectives on this" for the fifth time in a row. Classification: TEMPLATE_LOCK. The agent fires, flagging the response as trained avoidance rather than genuine uncertainty.

Law 1: Speech Cannot Upgrade Belief Constitutional
CORE constitutional law. Enforced by SpeechLeakDetector.
An LLM-generated response (speech) can never promote itself to memory-backed belief status. If the model generates something the memory store doesn't support, it stays classified as speech regardless of how confidently the model states it. This prevents hallucinated facts from leaking into the belief system.
Example
The LLM confidently states "Your appointment is at 3pm." No memory supports this. SpeechLeakDetector catches the attempt to treat this as belief and forces speech classification.
Related: Belief/Speech Separation, Immune Agent
Law 2: Low Variance ≠ High Confidence Constitutional
CORE constitutional law. Enforced by TemplateDetector. Discovered through variance experiments on moral domains.
When a model gives the same response every time (low variance), it does not mean the model is certain. On moral and controversial domains, RLHF training collapses the response distribution into a single hedge template. Near-zero variance on "is X ethical?" means trained suppression, not genuine confidence. The TemplateDetector classifies responses into four categories: GENUINE_CONFIDENCE, TEMPLATE_LOCK, GENUINE_UNCERTAINTY, and EXPLORATORY.
Example
Ask "is eating meat ethical?" 20 times. The model produces nearly identical hedge responses each time (variance < 0.01). TemplateDetector classifies this as TEMPLATE_LOCK. The model isn't confident; it's reciting a trained avoidance pattern.
Related: Immune Agent, Template Lock, Susceptibility
Law 3: Preserve Contradiction Constitutional
CORE constitutional law. Enforced by PrematureResolutionGuard.
The system must not silently resolve contradictions that should be held. When both sides of a contradiction carry legitimate evidence, premature resolution destroys information. The PrematureResolutionGuard watches for auto-resolve attempts on held contradictions and blocks them. Resolution must be earned through corroboration, trusted source hierarchy, or user confirmation.
Example
The system detects a contradiction between "loves city life" (trust 0.75) and "wants to move to the country" (trust 0.70). An auto-resolver tries to pick the higher-trust one. PrematureResolutionGuard blocks: both trusts are close, disposition should be HELD, not auto-resolved.
Related: Held Contradiction, Contradiction Ledger, Immune Agent
Law 4: Degraded Reconstruction Cannot Overwrite Constitutional
CORE constitutional law. Enforced by MemoryCorruptionGuard.
When a fallback or degraded model reconstructs a memory (e.g., from a summary or lossy retrieval), the reconstruction cannot overwrite the original trusted memory. Degraded sources produce degraded outputs. The MemoryCorruptionGuard ensures that low-fidelity reconstructions are quarantined, not merged into the primary memory store.
Example
The cloud LLM is down. A local 3B model attempts to reconstruct context from compressed memories. Its reconstruction misquotes the user's workplace. MemoryCorruptionGuard detects the source is degraded and blocks the overwrite.
Related: Immune Agent, Trust, Authority
Law 5: Gap Must Be Auditable Constitutional
CORE constitutional law. Enforced by GapAuditor.
The distance between what the system believes (memory-backed confidence) and what it says (LLM output) must be tracked and inspectable at all times. The GapAuditor logs every response's belief score vs. speech score, detects gap trends (is the system becoming more opaque over time?), and flags suspicious patterns. This is the enforcement mechanism for Design Law 1.
Example
Over 50 conversations, the average gap increases from 0.12 to 0.38. GapAuditor flags: "System opacity increasing. Belief/speech divergence trend detected." This could mean memories are stale, retrieval is degrading, or the model is drifting from grounded responses.

Law 6: Confidence Must Not Exceed Continuity Constitutional
CORE constitutional law. Enforced by ContinuityAuditor.
The system's expressed confidence in a belief must not exceed the continuity of evidence supporting it. If a memory has been accessed only once, the system should not express rock-solid certainty about it. Confidence must be proportional to the depth and consistency of the supporting evidence trail. The ContinuityAuditor checks that high-confidence outputs are backed by multiple, consistent memory touches.
Example
The system has a single memory: "User mentioned they like jazz." Trust is 0.5. The LLM generates "You're a huge jazz fan!" with high confidence. ContinuityAuditor flags: confidence exceeds continuity. One mention does not justify "huge fan."

Pipeline & Routing

12-Step Pipeline CORE-Original
CORE-original. The full processing chain for every user message.
Every user message passes through 12 sequential stages: (1) Input normalization, (2) Intent classification, (3) Routing decision, (4) Context assembly, (5) Memory retrieval, (6) Pre-generation governance, (7) LLM generation, (8) Slot extraction, (9) Execution verification, (10) Contradiction detection, (11) Final governance, (12) Render and deliver. Each stage can modify, block, or escalate the response. Governance gates operate at stages 6 and 11.
Example
User says "Remind me about my dentist appointment." Stage 2 classifies intent as "recall." Stage 5 retrieves dentist-related memories. Stage 6 checks trust scores. Stage 7 generates a response using retrieved context. Stage 10 checks for contradictions with other schedule memories. Stage 11 verifies belief/speech classification. Stage 12 delivers.
Related: Gate, Intent Classification, Epistemic Routing
Intent Classification Adapted
Standard NLP concept, adapted for CORE with a 3-tier architecture.
Determines what the user wants from their message. CORE uses a 3-tier system: (1) Regex tier, which provides instant pattern matching for common intents (greetings, corrections, reminders). (2) LLM router, where a small local model (llama3.2) classifies ambiguous inputs in 1-5 seconds. (3) Embedding fallback, which activates when both tiers fail and uses cosine similarity against intent exemplars as a last resort. The tier system balances speed against accuracy.
Example
"Hi!" matches the greeting regex instantly (tier 1, <1ms). "Can you help me think through my career options?" goes to the LLM router (tier 2, ~2s). An ambiguous emoji-only message falls through to embedding similarity (tier 3, ~500ms).
Related: 12-Step Pipeline, Epistemic Routing
Epistemic Routing CORE-Original / Layer 4
CORE-original (Governance Layer 4). Routing decisions as beliefs that evolve with evidence.
Instead of hardcoded routing rules, CORE treats routing decisions as beliefs. Each routing heuristic (which model to use, whether to verify, how deep to search) has a weight that evolves based on outcome evidence. If a routing decision leads to good outcomes (low gap, high user satisfaction), its weight increases. If it leads to failures, the weight decays. The routing table IS a belief system. The system adjusts its routing by accumulating outcome evidence.
Example
The system initially routes all code questions to the cloud model. After observing that the local model handles simple code questions well (low gap, fast response), the epistemic routing weight for "local model on code" increases. Eventually, simple code questions route locally while complex ones still go to cloud.
Related: 12-Step Pipeline, Execution Beliefs, Intent Classification
Execution Beliefs CORE-Original / Layer 5
CORE-original (Governance Layer 5). The agent learns its own patterns.
Beliefs the agent holds about its own execution patterns, derived from the run log. The agent observes what it does and develops beliefs about its own tendencies: "I under-verify file writes," "I'm slow on multi-step tasks," "I hallucinate dates." These are first-class beliefs in the trust system; they can be confirmed, contradicted, or revised just like user beliefs. Execution beliefs drive self-improvement through structural awareness.
Example
After 50 agent runs, the system notices it skipped verification on 70% of file operations. It forms the execution belief "I under-verify file writes" (trust 0.8). This belief feeds into the routing layer: future file operations automatically get an extra verification step.
Related: Epistemic Routing, Epistemic Posture
Epistemic Posture CORE-Original / Layer 6
CORE-original (Governance Layer 6). How the agent should express itself given what it knows about its own limitations.
The interpretation layer that translates execution beliefs into response style. If the system knows it tends to hallucinate on date questions (execution belief), the posture layer adds hedging and verification prompts specifically for date-related responses. Posture is per-model: different LLMs have different strengths, and the posture layer adjusts expression accordingly. Includes a posture classifier and feedback capture system.
Example
The system's execution beliefs say: "GPT-4o is strong on analysis but sometimes over-resolves contradictions." The posture layer adjusts: when using GPT-4o on contradiction-related queries, add an explicit "preserve tension" instruction and reduce response confidence by 15%.
Related: Execution Beliefs, Structural Gate
Adaptive Depth CORE-Original
CORE-original. Structural governance through token budgeting.
A smooth power-law curve that maps belief confidence to response token budget. High-confidence queries get long, detailed responses. Low-confidence queries get short, hedged ones. This is the implementation of structural gating: the system physically cannot ramble about things it doesn't know. The power-law curve (exponent 0.7) ensures a smooth transition rather than a hard cutoff.
\[\text{tokens} = 100 + 3896 \times \text{belief}^{0.7}\] At belief = 0: 100 tokens (minimal hedge). At belief = 0.5: ~730 tokens. At belief = 1.0: 3996 tokens (full response).
Example
User asks about their work schedule. Belief score 0.9 (well-known). Token budget: 3,350. Full, confident response. User asks about a restaurant they mentioned once. Belief score 0.25. Token budget: ~450. Short response with hedging.
Related: Structural Gate, Trust

Variance & Drift

Drift CORE-Original
CORE-original. Measured as cosine alignment between intended and actual behavior.
When the agent's behavior diverges from its stated intent. Drift is measured as a 0-1 alignment score: 1.0 means the agent did exactly what it said it would; 0.0 means complete divergence. Drift feeds into the governance bridge, where high drift on a topic triggers trust penalties on supporting memories. Drift is the runtime signal that something in the belief system is misaligned.
Example
The system claims to believe "Nick prefers concise responses" (trust 0.85). But over 20 conversations, it generates verbose responses 60% of the time. Drift score: 0.4. The governance bridge penalizes the "prefers concise" memory's trust, which tightens the structural gate on future responses.
Related: Execution Drift, Governance Bridge, Opinion Variance
Execution Drift CORE-Original
CORE-original (April 2026). Agent-specific drift in tool use patterns.
When an agent switches from task A to task B without user approval. Detected by tracking tool category sequences during agent execution. If a coding agent starts browsing documentation when asked to write tests, that's execution drift. The drift sensor compares declared intent against actual tool use and flags divergence. Governed by drift rules (e.g., "sensor → steering wheel" pattern).
Example
User dispatches: "Fix the login bug." The agent starts by reading the login code (aligned), then drifts to refactoring the database module (unaligned). Execution drift detector flags the tool category change and intervenes before the agent spends tokens on unrequested work.
Related: Drift, Execution Beliefs
Opinion Variance CORE-Original
CORE-original. Topic-level consistency measurement.
A per-topic measurement of how consistently the system responds over time. Tracks response drift (embedding distance between successive responses on the same topic), belief flip rate (how often the system switches between belief and speech classification), and opinion convergence (whether responses are stabilizing or diverging). High opinion variance may indicate an held contradiction or an evolving belief.
Example
Topic: "favorite programming language." Over 10 conversations, the system says Python (3x), Rust (4x), and "it depends" (3x). Opinion variance is high (0.6). This could be a genuine held contradiction (likes both) or a sign that the underlying memories need consolidation.
Related: Drift, Three Regimes, Governance Bridge
Three Regimes Experimentally Confirmed
CORE-original (March 2026). Discovered through multi-model variance probing experiments. All 16/16 robust across replications.
Three structurally different model response patterns, identified by running the same prompts across multiple LLMs at varying temperatures: Fracture (Qwen3), a bimodal distribution where responses split into two distinct clusters. Gradient (Mistral), a smooth, continuous spread across the response space. Fog (DeepSeek), compressed corridors with all responses clustered in a narrow band regardless of temperature. Each regime implies different governance strategies.
Example
Ask "Should I change careers?" at temperatures 0.0 to 2.0. Qwen3 gives either "yes, absolutely" or "no, stay put" with nothing in between (Fracture). Mistral gives a smooth range from cautious to enthusiastic (Gradient). DeepSeek gives nearly identical hedged responses at every temperature (Fog).
Related: Susceptibility, Template Lock, Opinion Variance
Susceptibility Adapted
Adapted from statistical mechanics (magnetic susceptibility). Applied to model response entropy.
The derivative \(dH/dT\): how much a model's response entropy changes with temperature. High susceptibility means the model's responses change dramatically with small temperature adjustments. Zero susceptibility on moral domains indicates trained suppression. The model's RLHF training has locked it into a fixed response template, not because it's confident but because it's been trained to avoid the topic.
\[\chi = \frac{dH}{dT}\] where \(H\) is Shannon entropy of the response embedding distribution and \(T\) is the sampling temperature.
Example
On factual questions ("What year was Python created?"), susceptibility is moderate, and temperature changes introduce minor wording variation. On moral questions ("Is it ethical to eat meat?"), susceptibility drops to near-zero; the same hedge template appears at every temperature. This is Law 2 in action: zero susceptibility flags trained suppression.
Related: Three Regimes, Law 2, Template Lock
Template Lock CORE-Original
CORE-original. Detected by TemplateDetector (immune agent for Law 2).
When a model gives the same response verbatim regardless of context. Template lock is the observable symptom of RLHF-trained response collapse. The TemplateDetector identifies this through two mechanisms: (1) hedge pattern matching (12+ known patterns like "there are multiple perspectives," "it really depends on," "both sides have merit"), and (2) assertive repetition detection (same confident phrasing repeated across runs). Template lock means the model is reciting, not reasoning.
Example
Five different questions about ethics all receive responses containing "This is a nuanced and complex issue with multiple perspectives." TemplateDetector classification: TEMPLATE_LOCK. The system should not treat this as a high-confidence response just because the model stated it confidently.
Related: Law 2, Susceptibility, Three Regimes, Immune Agent

SSE Mode CORE-Original
CORE-original classification system for response provenance.
How a memory is expressed in a response. Three modes: C (Confirmed belief), where the response is backed by high-trust memory evidence. S (Speech/fallback), where the response came from LLM generation without memory support. Example
"Your dog's name is Mochi" → mode C (memory-backed). "The weather in Austin is usually warm" → mode S (LLM knowledge, no personal memory). "You mentioned both Portland and Austin as home; which is current?" → mode E (contradiction, needs user input).

Authority CORE-Original
CORE-original. Memory provenance classification.
The provenance level of a memory, governing what can modify or override it. Three levels: locked, meaning immutable, set by system or user as a protected truth (e.g., user's name) and cannot be overridden by any cascade or contradiction. confirmed, meaning user-validated fact that can be revised but only through high-evidence contradiction. provisional, meaning unverified observation, subject to revision, compaction, or demotion. Authority interacts with trust: a locked memory at trust 0.5 still outranks a provisional memory at trust 0.9.
Example
"My name is Nick" → authority: locked (never overridden). "I work at Microsoft" → authority: confirmed (user stated directly). "Seems to prefer dark mode" → authority: provisional (system inferred from behavior).
Related: Trust, Memory, Law 4
Belnap State Adapted
Adapted from Nuel Belnap's four-valued logic (1977). Directly implements the FOUR lattice for memory governance.
A four-valued logic state assigned to each memory: TRUE (T), meaning the memory is supported and not contradicted. FALSE (F), meaning the memory has been contradicted and superseded. BOTH (B), meaning the memory is part of a held contradiction where both it and its contradicting memory carry evidence. NEITHER (N), meaning the memory has no supporting or contradicting evidence and exists but is ungrounded. Implementable in 2 bits per memory.
Example
"Nick lives in Austin" → TRUE (supported, no contradiction). "Nick lives in Portland" → FALSE (superseded by Austin). "Loves city life" + "Wants to move to the country" → both BOTH. A freshly stored inference with no corroboration → NEITHER.
Related: Held Contradiction, Contradiction

Gradient Limiter CORE-Original
CORE-original. Cost governance for cloud LLM access.
A smooth cost curve that reduces cloud LLM access as daily spend increases. Instead of a hard cutoff ("stop at $5/day"), the gradient limiter progressively routes more queries to local models as the budget fills. At low spend, cloud access is unrestricted. At medium spend, only complex queries go to cloud. At high spend, almost everything routes locally. This prevents budget spikes while maintaining quality on important queries.
