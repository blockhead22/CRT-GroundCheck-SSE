1. Scope and truth boundary

This page documents the current Aether Workbench and sidecar request path. It does not claim that every module, experiment, or mathematical idea in the Aeteros archive is active in that path.

Important distinction: research code can exist, import successfully, or pass an isolated test without being part of a normal Workbench turn. Current capability claims here are limited to verified source call sites and user-visible receipts.

Aether

The current dogfooded personal-agent product: Workbench UI, local sidecar, governed context release, renderer selection, traces, and review surfaces.

Aether Core repository

The local codebase containing the substrate, sidecar, governance mechanisms, tests, adapters, and research lineage.

Aeteros Core boundary

A small reusable audit contract currently being extracted. It does not yet represent every mechanism described across the research archive.

Aeteros

The umbrella identity for the project and research. It is not presented here as an established company, certification authority, or finished hosted platform.

4. Continuity and memory

Aether does not paste an unrestricted archive into each prompt. It distinguishes several roles:

Governed evidence

Durable substrate states that are relevant and released for the current question. Contradictions can be held instead of flattened into false certainty.

Recent conversation

A bounded same-conversation packet used for references and conversational continuity. It is not automatically treated as durable factual evidence.

Review-only candidates

Reflection, support, learning, and autobiographical suggestions can be surfaced without silently becoming confirmed memory.

Confirmed writes

Durable changes require route and persistence authority and leave a receipt. Passive learning can accumulate evidence, but the review boundary remains inspectable.

Raw hidden chain-of-thought is not the continuity substrate. Aether stores bounded public traces, decisions, evidence packets, and outcomes instead.

5. Renderer policy

The selected model is the answer renderer for normal generative turns. Local and hosted models receive the same governed role separation: the model proposes language and, when allowed, tool requests; Aether owns context release, capability grants, persistence, and receipts.

What “Thinking” means: Workbench can show public progress events, planning state, tool activity, and verification state. It does not expose or claim to store a provider's private chain-of-thought.

6. Tool boundary

The normal model-proposable catalog is intentionally small:

ToolPurpose
workspace_searchSearch workspace files for a query or symbol.
workspace_readRead a bounded line range under configured workspace roots.
workspace_listList one directory under configured workspace roots.
document_searchSearch saved Workbench documents and notes.

Proposals are capped, queries and read spans are bounded, and shell, writes, patches, policy changes, and memory writes are excluded from this model grant. Separate deterministic and approval-controlled paths can perform broader actions.

MCP exposes a different substrate-management surface. MCP availability must not be confused with tools automatically available to a Workbench renderer.

7. Research mechanisms not claimed as live

The repository contains substantial work on Wobble, Fidelity Mirror, belief backpropagation, GroundCheck, geometric memory, immune agents, structural tension, and older CRT/personal-agent pipelines. Those remain useful research and implementation history.

This page does not claim that those mechanisms wrap every current Workbench response, that Claude Code is autonomously dispatched, that an OpenAI-compatible public proxy exists, or that the system is legally certified or externally validated.
