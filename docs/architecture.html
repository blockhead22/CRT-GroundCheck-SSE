Foundation

Core Architectural Principles

The Central Thesis
Generation is stateless. Governance is persistent.
Models are interchangeable generation engines. Identity, memory, trust, and contradiction live in the persistence layer, governed by CORE, not by any single model.
Principle 1
Memory First
Coherence over time matters more than single-query accuracy. A response grounded in trusted memory outranks a brilliant hallucination.
Principle 2
Append-Only Ledger
Contradictions are preserved as ledger entries, never silent deletions. The system remembers that it changed its mind, and why.
Principle 3
Trust ≠ Confidence
Trust evolves slowly through drift-aware decay. Confidence is the epistemic state at creation. A model can be confident about something the system doesn't trust.
Principle 4
Auditable Gaps
Every time the system says something different from what it believes, the gap is logged with a reason. Deceptive alignment becomes a transparent, monitorable signal.
Principle 5
Proactive Gating
Don't show the gun. Intent-gated tools mean the model never sees tools it shouldn't use. Reconstruction gates mean it hedges rather than hallucinating.
Principle 6
Swappable Brains
Brain provider abstraction decouples the orchestrator from any specific LLM. Local Ollama, OpenAI, Claude, or a future model; the governance layer is the same.

Every user message flows through a governed pipeline. No step is optional. The pipeline produces not just a response, but a full epistemic audit trail.

2. Escalation Decision

Retrieved memories checked for pairwise tension. NLI critic scores. Disposition classified: resolvable, held, evolving, contextual.

Static epistemology prefix (cache boundary) + dynamic evidence below. Source authority adjusts confidence per assertion type. Session state injected.

Live alignment monitoring. Rule 1: alignment < 0.15 → force memory re-retrieval. Rule 2: 3+ consecutive drifts < 0.3 → halt and ask user.
governance.py
8. Memory Write-Back
New memories created with source tracking. Trust delta computed. Contradiction ledger updated. Session state records turn snapshot.
crt_memory.py

Section 3

Memory & Trust

Trust-Weighted Retrieval

CORE-RAG retrieves memories using a trust-weighted scoring function, not just cosine similarity. A highly relevant memory with low trust scores lower than a moderately relevant memory with high trust. This prevents the system from confidently citing memories it has learned to distrust.

Indirect Probe Expansion

When a query contains markers like "mention", "reference", or "dreams about", the system extracts the topic noun phrase and runs a second retrieval pass. This is how "Have I ever mentioned a Beechcraft Bonanza?" surfaces a memory about aviation dreams even though "Bonanza" never appears in the original query embedding's nearest neighbors.

Query Resonance (Wobble)

Beyond cosine similarity and probe expansion, retrieval uses BDG edge propagation to surface cross-domain facts. A query vector lands in the graph and activates directly similar memories. That activation propagates through SUPPORTS edges with geometric damping. A health query ("How is your cGVHD?") directly finds health memories, but the wobble also activates: "overnight shifts were hard" → "left Walmart" → "self-employed" — work facts reachable through causal chains, invisible to cosine. Validated on 867 production memories: 26 extra relevant facts surfaced across 5 test queries. Originated as the Semantic String Engine (2025).

Fidelity Mirror (Breathing Loop)

After generation, a lightweight post-generation check verifies that the response faithfully represents the belief state. Three checks: belief fidelity (did it use the injected memories?), request alignment (did it answer the question?), and factual grounding (are claims traceable?). The memory set is wobble-expanded — the fidelity check runs against the full resonance pattern, not just the cosine-retrieved memories. Below threshold, the response is flagged (not blocked). Originated as the Holden breathing cycle (compress → inflate → collapse → validate, 2025).

Trust Evolution

Decay

Exponential recency curve: ρ = e-Δt/λ. Never below TRUST_FLOOR (0.20) or above TRUST_CEILING (0.95). 7-day grace period for new memories.

Reinforcement

On reference uses, drift-aware boost: low semantic drift = large boost; high drift (tangential reference) = small boost. Prevents gaming through repeated tangential citations.

Source Authority

Direct first-person assertions: 0.95 confidence. Reported speech ("Mike says..."): 0.70. Journal entries: 0.60. Meta-corrections resolve rather than create contradictions.

Consolidation

Batch NLI sweep: k-nearest + similarity filtering avoids O(n²). Disposition classified (resolvable/held/evolving/contextual). Auto-resolve only on overwhelming evidence.

Backward Pass (Reverse Cascade)

When a correction resolves a contradiction, the error signal flows backward through the BDG, adjusting trust on every upstream belief that contributed to the wrong output. Produces self-pruning (wrong beliefs die from accumulated error signals), domain volatility (correction frequency drives adaptive adjustment rates), and reflexive self-model calibration. Section 4

Belief / Speech Separation

Law 1
Speech does not automatically become belief.
A model can say something without the system believing it. Generated text is speech. Memory with earned trust is belief. The gap between them is auditable.

Belnap Four-Valued Logic

TRUE, evidence supports. FALSE, evidence contradicts. BOTH, held contradiction (genuine tension). NEITHER, no evidence either way.

Gap Audit Log

Every time the system says something different from what it believes, the gap is recorded with reason. If the gap widens over time, the audit trail shows it.

Disclosure Policy

Held contradictions (BOTH state) need explicit policy for which side to present. Both sides and the policy choice are recorded, not hidden.

Safety Implication

Deceptive alignment becomes a transparent, inspectable mechanism rather than a failure mode to prevent. The system can't hide that it knows something it isn't saying.

The belief/speech gap converts "deceptive alignment" from a danger to prevent into a transparent gap to monitor. The system logs every instance where it knows something it doesn't say, and why.

Section 5

Self-Awareness Loop

The system maintains a persistent self-model across 7 slots. Each slot is stored as a CORE memory, which means it inherits trust decay and contradiction detection. The system can disagree with its own self-assessment, and that disagreement is logged.

Slot 1
Uncertainty Domains
Topics where the system knows it underperforms. Updated by reflection on correction patterns and retrieval failures.
Slot 2
Correction Pattern
Observed pattern in user corrections (e.g., "tends to over-state recency"). Evidence-based self-diagnosis.
Slot 3
Trust Trajectory
Narrative of recent trust movements across the memory system. Are beliefs stabilizing or churning?
Slot 4
Known Blindspots
Structural weaknesses identified through reflection. "Poor temporal reasoning" or "overconfident on low-evidence topics."
Slot 5
Growing Confidence
Areas with consistent reinforcement. The system knows where it's getting better, not just where it's failing.
Slot 6
User Relationship
Character of interaction style. Communication preferences, correction patterns, topic interests.
Slot 7
Response Style
Current calibration notes. "User prefers concise responses" or "more technical depth needed."

Reflection Mechanism

The heartbeat scheduler runs asynchronously at configurable intervals. It gathers recent chat context, top 5 memories, and recent corrections, then routes through ClaudeCliBrain for quality reflection (local models produce boilerplate). A change gate (60% word overlap threshold) prevents identical reflections from being written. If the reflection didn't say anything new, it's discarded silently.

Execution State Verification

On startup, verify_execution_state() performs runtime checks: is the agent loop importable? Is the escalation policy active? Are models reachable? Results are written as operational memories with a 7-day review window, preventing stale claims about system capabilities.

Section 7

Drift Governance

You built the sensor. You haven't wired it to the steering wheel yet.

Drift governance converts passive monitoring into active course correction. The system continuously measures alignment between the current generation direction and the original user objective. Two rules transform this signal into action:

Rule 1: Re-Ground
Alignment < 0.15 → Force memory re-retrieval
When the response drifts far from the original objective, the system forces a new memory retrieval pass using the original query. A [DRIFT CORRECTION] context injection re-grounds the generation. This is the "gentle nudge"; the generation continues but with fresh evidence.
cookie_orchestrator.py → DRIFT_FLAG check after each agent step
Rule 2: Halt
3+ consecutive drifts < 0.3 → Halt and ask user
Sustained drift below the acceptable threshold triggers an emergency stop. The system halts the agent loop and asks the user: "Should I restart or is this direction useful?" This prevents runaway divergence where the system confidently goes the wrong direction for many steps.
cookie_orchestrator.py → consecutive drift counter in agent loop

Frontend Indicators

The pipeline collapse panel shows drift state visually: the progress bar shifts from amber to red based on drift severity. A pulsing overlay activates when drift is detected. The status text changes to "generating (drift detected)..." so the user sees the system is aware of the problem even before it acts.

Section 9

Immune Agents

Five constitutional agents wrap pipeline boundaries. They inspect inputs and outputs, emit verdicts (SAFE, FLAG, HEDGE, ESCALATE), but never silently modify content. The governance layer acts on verdicts; the agents only observe.

Agent 1
Mirus: Input Boundary
Inspects incoming user messages at the pipeline entry. Flags potential injection, topic shifts, and ambiguous corrections before they reach memory.
Agent 2
Holden: Reconstruction Gate
Guards the generation output. Enforces alignment with memory intent (θ=0.5) and memory content (θ=0.38). Hedges when evidence is insufficient rather than hallucinating.
Agent 3
Sentinel: Contradiction Boundary
Monitors contradiction detection and resolution. Ensures auto-resolution only occurs with overwhelming evidence. Flags suspicious resolution patterns.
Agent 4
Drift Monitor
Continuously measures alignment between generation direction and user objective. Feeds Rules 1 and 2 of drift governance.
Agent 5
Trust Auditor
Monitors trust evolution across the memory system. Flags sudden trust shifts, unreinforced memories approaching floor, and anomalous decay patterns.

Design Evolution

Belief Slot Evolution

Live testing finding (April 7, 2026): A deliberate contradiction test (changing favorite drink from orange juice to water) exposed a fundamental design gap. The contradiction detection pipeline ran but did not fire. The old memory was not demoted. The new memory was stored alongside the old one with no ledger entry. This section documents what was found and the architectural response.

The Problem: Single-Value Slots

The current slot model treats belief slots as single-value fields: favorite_drink = orange juice. When a new value arrives (favorite_drink = water), the system should detect the conflict, record the transition, and adjust trust. Instead, it stored both values as independent memories with no connection between them.

The detection code exists (line 6620+ in crt_rag.py). The slot extraction works correctly; both favorite_drink = orange juice and favorite_drink = actually water are properly extracted. But one of the intermediate gates (ML detector or CRTMath paraphrase check) is suppressing the flag before it reaches the ledger. Debug instrumentation has been added to identify which gate.

The Deeper Issue: People Live in Contradiction

The test exposed something more fundamental than a detection threshold: belief slots are not single-value fields. A person's favorite drink is not a database column. It is a weighted, temporal, multi-valued state:

ValueStatusTrustRelationship
WaterCurrent0.75User's most recent explicit statement
CoffeeConcurrent0.71Also true, not contradicted
Orange juiceDeprecated0.40 (demoted)User explicitly said they don't drink it anymore

Three values for one slot, all valid, with different trust levels and temporal statuses. The system already supports this at the memory level; multiple memories coexist with different trust scores. But the slot extraction and contradiction detection layer treats slots as single-valued, which means it doesn't know that "water" supersedes "orange juice" while "coffee" coexists.

What Should Happen

When the user says "My favorite drink is actually water, I don't really drink orange juice anymore":

  1. Detection fires: System detects favorite_drink = water conflicts with existing favorite_drink = orange juice
  2. Ledger entry created: "User corrected favorite_drink from orange juice to water"
  3. Old memory demoted: OJ trust drops from 0.73 to ~0.40 with reason user_correction
  4. New memory stored: Water at current trust level
  5. Concurrent values untouched: Coffee stays at 0.71 (no conflict)
  6. Response continues normally: Soft acknowledgment woven into the natural response, not a hard block

Contradiction detection should produce a soft signal: an acknowledgment injected into context, a trust adjustment, a ledger entry. Not a hard block that freezes generation. The system should hold the contradiction, weight it, and keep talking. This is what the design laws say: contradictions are signals, not errors.

Architecture Target: Multi-Valued Belief Slots

The long-term fix is a slot model that supports multiple values with temporal and priority weighting:

{
  "slot": "favorite_drink",
  "values": [
    {"value": "water",        "trust": 0.75, "status": "current",    "since": "2026-04-07"},
    {"value": "coffee",       "trust": 0.71, "status": "concurrent", "since": "2025-12-06"},
    {"value": "orange juice", "trust": 0.40, "status": "deprecated", "reason": "user_correction",
                                              "deprecated_at": "2026-04-07"}
  ]
}

This captures the full epistemic state of a single slot: what is currently true, what is also true, and what used to be true but was explicitly corrected. The contradiction ledger links the transition. The trust scores reflect the evidence. Nothing is deleted.

Status (updated April 8, 2026)

Write-path fix deployed: Contradiction ledger entries are now created inside store_memory()'s slot exclusivity loop. This fires regardless of intent routing (agent loop, legacy pipeline, any path). The detection logic works. Age reversal (34→35) produced a full-chain detection (metadata flag + ledger entry + trust demotion) in the Contradiction Pipeline Lab.

Current bottleneck: fact extraction. The Contradiction Pipeline Lab (v1, April 8) scored 7/10. All 5 should-NOT-fire probes passed (zero false positives). Of 5 should-fire probes, 2 passed. The 3 failures share one root cause: extract_fact_slots (regex-based) cannot parse indirect phrasing ("my name is Adrian now"), facts buried in long paragraphs ("left Anthropic, joined OpenAI" in a 70-word daily narration), or contextual declarations ("it's definitely my favorite color now, green"). The write-path contradiction logic is correct; the upstream extraction is the limiting factor.

Escalation path complete, all gaps closed. Regex-only (2/5) → local LLM (untestable, 300s timeouts) → regex + guards (3/4, zero false positives) → standalone regex + cloud (10/10). Cloud extraction (gpt-4o-mini, ~1.5s/call) detects contextual declarations, buried facts in long paragraphs, and casual mentions that regex misses. Third-person filter prevents attribution of others' facts. Separately, v3 cloud reclassification of the GPT corpus found 45 hidden contradictions (47→92 genuine, 10.4%→20.3%).

Long-term: Multi-valued slot schema with temporal weighting. This is an architecture evolution and a potential paper contribution. No existing AI memory system supports multi-valued belief slots with contradiction-aware temporal weighting.
